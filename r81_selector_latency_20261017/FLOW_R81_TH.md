# R81: ลดการรอโมเดลในขั้นเลือกหัวข้อ

## หลักฐานเริ่มต้น

ผลจริงจากผู้ใช้ `r79_connection_diagnostics_20261017/user_results/20261017T064224Z-0f14c1`: คำถาม `Can I bring my own input peripheral?` ใช้ HTTP 7.154 วินาที ตัวเลือกข้อมูลเกิด TimeoutError แต่คำตอบสุดท้ายเป็นเมนูถามยืนยันหัวข้อ จึงไม่ควรนำการตอบสำเร็จของทั้งบทสนทนาไปอ้างว่าโมเดลเลือกหัวข้อได้สำเร็จ

การถาม READY โดยตรงสำเร็จ 6.953 วินาที มี load_duration 6.657 วินาที แต่เป็นคนละคำขอและคนละ prompt กับ selector จึงยังสรุปไม่ได้ว่า selector หมดเวลาเพราะโหลดโมเดล คิว RAM หรือ GPU ส่วนใด

## Flow ที่นำไปทำ

1. เก็บ hash และสำรองเฉพาะไฟล์ที่จะเปลี่ยนใน R78 รักษา DB และการแก้ R80 ไว้
2. ดึงผู้สมัครตามกติกาเดิมและตรวจหัวข้อ profile ที่เข้ากับ task/context/ownership
3. เฉพาะผู้เรียกที่รับรองว่าต้องถามยืนยันหัวข้อ และผู้สมัครทุกตัวเป็น profile ที่เข้าเกณฑ์: ส่งต่อไปถามยืนยันทันที ไม่เริ่ม model lock หรือ HTTP ไม่อ้างว่าเข้าใจความหมายตรงกันแล้ว
4. หากมีผู้สมัครทั่วไปปะปน หรือ profile ไม่เข้าเกณฑ์: ใช้ selector เดิม รวมถึง scoped lookup ที่ไม่ได้ขอใช้ทางลัดนี้
5. การเลือกหัวข้อของผู้ใช้ยังต้องตรวจ state ที่เซิร์ฟเวอร์ออกให้ fingerprint แหล่งข้อมูล และ revision ปัจจุบัน ก่อนอ่านข้อมูลจริง
6. การตอบ “ใช่ แต่…” “ไม่ใช่…” เปลี่ยนอุปกรณ์ เปลี่ยนเจ้าของ ใช้แข่งขัน หรือเพิ่มเงื่อนไข ยังผ่านตัวตรวจเดิม ไม่ยกการยืนยันเป็นสิทธิ์ตอบทุกเงื่อนไข
7. เพิ่มเวลา retrieval / model lock / admission / HTTP / total พร้อม budget และขนาดคำขอ หากได้รับ response ให้บันทึก duration จาก Ollama โดยแปลง ns เป็น ms และจำนวน token แยกจากคุณภาพคำตอบ
8. ตรวจ budget อีกครั้งหลังรอ lock/gate ก่อนส่ง HTTP ไม่เรียกด้วย timeout=0 และคืน lock เสมอ
9. แยก timeout, transport, schema, semantic rejection ไม่เพิ่มเพดานเวลา ไม่เพิ่ม token เพื่อกลบปัญหา
10. ทดสอบเฉพาะเส้นทางที่เกี่ยวข้องด้วย fixture และข้อมูลจริงแบบอ่านเท่านั้น ก่อนลงไฟล์ R78 โดยตรวจ hash ก่อนเปลี่ยน
11. ตรวจจริงหลัง restart ผ่าน helper ที่ยืนยัน installation/profile/source fingerprint และ LLM ON; สร้างผลโฟลเดอร์ใหม่ทุกครั้ง

## ตรวจทานและปรับ Flow สามรอบ

- รอบ 1: การข้ามโมเดลทั้งหมดอาจทำให้เสียการเลือกข้อมูลทั่วไป → จำกัดเฉพาะ all-profile + eligible + caller opt-in และเพิ่ม mixed/default-call tests
- รอบ 2: การได้ HTTP 200 ไม่พิสูจน์คำตอบถูก หรือหมดเวลาไม่ได้แปลว่าโมเดลไม่มี → แยก transport/schema/content และไม่ให้ทางลัดอ้าง model success
- รอบ 3: ทดสอบผ่านในไฟล์ใหม่แต่เว็บยังใช้โค้ดเก่าได้ → helper ต้องเทียบ source fingerprint ใน health กับไฟล์ติดตั้ง ถ้าไม่ตรงให้หยุดพร้อมแจ้ง restart ไม่ใช้ผลโค้ดเก่ามาให้คะแนนใหม่

## เกณฑ์จบและข้อจำกัด

- ไม่มีการแก้เนื้อหา นโยบาย ราคา approvals หรือ releases
- ภาษาทั้งสองยังต้องถามยืนยันก่อนให้ข้อเท็จจริงในกรณีคำพ้องที่ยังไม่พิสูจน์
- ทดสอบควบคุมพิสูจน์ branch และ contract ได้ แต่ไม่ใช่เวลาโมเดลจริงหรือความแม่นยำทั่วไป
- เครื่องมือปัจจุบันถูกปฏิเสธ loopback ด้วย WinError 10013 จึงต้องให้ผู้ใช้เปิด helper จาก Windows เพื่อเก็บ HTTP จริง โดยไม่เปลี่ยน firewall หรือยกระดับสิทธิ์
- ความเร็วของ selector อื่นต้องดูผล timing จริงต่อ ไม่สรุปว่าทุกคำถามหายช้าแล้ว
