# R68 — ตรวจข้อมูลตกหล่นและเติม Format กลางอย่างมีหลักฐาน

## เป้าหมายและขอบเขต

ตรวจข้อมูลธุรกิจทุกกลุ่มในโปรเจกต์ที่อ่านได้ เทียบทั้งไฟล์ก่อน canonical และ R67 แล้วเติมสิ่งที่พิสูจน์ได้ลงช่องที่ตัวอ่านใช้จริง เก็บ revision/source เก่าไว้ และตรวจว่าการเพิ่มข้อมูลไม่สร้างเกมที่เปิดให้เล่น เครื่องจริง ราคา หรือสิทธิ์การใช้บริการขึ้นเอง

ฐานเริ่มต้นคือ R67 จำนวน 596 heads โฟลเดอร์โปรเจกต์จริงยังแยกจาก workspace ใช้ candidate06.sqlite เป็นผลสุดท้ายเท่านั้น ฐาน common.sqlite และ candidate02–05 เป็นหลักฐานระหว่างพัฒนา ห้ามเลือกแทนฉบับสุดท้าย

## Flow

1. สำรองฐาน R67 ด้วย SQLite backup เป็น before.sqlite และ candidate แยก ตรวจ source manifest 1,402 ไฟล์กับโปรเจกต์จริง
2. ตรวจโครงสร้าง raw business files 38 ไฟล์ระดับบน และแฟ้ม canonical/หลักฐานทั้งหมดที่ snapshot ไว้ แยกข้อมูลธุรกิจออกจาก routing, regex, test fixture, derived projections และ review queue
3. เทียบช่องกับต้นทางโดยอาศัยตัวตนที่ชัดเจน:
   - เกม: ชื่อเต็มที่ normalize เครื่องหมาย/ช่องว่างแล้วตรงกันหนึ่งรายการ ไม่รวมคนละภาค
   - ปุ่ม: เกม + แพลตฟอร์ม + แถวเดิม ไม่ใช้แค่ชื่อปุ่ม
   - กฎ: rulebook ID + ข้อความตรงกัน ไม่ใช้เพียงชื่อเกม
   - นโยบายบริการ: claim เดียวกับที่ผู้ใช้ตอบไว้ ไม่ขยายเงื่อนไข
4. เติมช่องเดิมก่อน หากความหมายต่างกันให้เพิ่ม optional field พร้อม schema, template, catalog, labels, query cues และ reader context
5. ใส่ immutable source snapshot, SHA256, locator, original value, mapped value และกฎแปลงทุกครั้ง; append revision โดยไม่ approve/publish
6. ตรวจ schema ทั้งกราฟก่อนบันทึก บันทึก FK targets ก่อน references และตรวจความคงเดิมของ revisions/sources/validity/review/เกมที่ offered
7. ทดสอบ source text ที่ปลายคำบรรยายด้วย ไม่ตรวจเพียงคำขึ้นต้น ทดสอบค่าที่ถามผ่านช่องตรง เช่น สเปกต้องมี CPU/RAM/GPU
8. ตรวจชื่อเรียกทุกชื่อที่เพิ่ม และตรวจคำถามเกมคนละภาค/แพลตฟอร์มมือถือ ใช้ชุดนี้เป็นขอบเขตหลักฐาน ไม่ถือว่าพิสูจน์ทุกคำถาม
9. ทดสอบ common แบบ OFF/ON, ชุดที่รักษาพฤติกรรมเดิม, follow-up และหน้าเจ้าของแบบฟังก์ชัน เก็บคำตอบ/trace/error แยกแต่ละรอบ
10. เตรียม delivery ที่เทียบ conflict กับไฟล์จริงและมี backup ก่อนแก้ ขอสิทธิ์ผ่านระบบหากต้องเขียน Downloads ห้ามย้ายผ่านช่องทางอื่นเพื่อหลบ sandbox

## การทบทวน 3 รอบที่ทำจริง

### รอบ 1: ขอบเขตการตรวจเดิมแคบเกินไป

R67 ตรวจข้อความ canonical และ curated แล้ว แต่คำบรรยาย curated ถูกตัดจาก raw อีกชั้นหนึ่ง ต้องใช้ data/sources/our_games_raw.jsonl เทียบด้วย พบ 23 รายการที่ข้อความภาษาต้นทางสั้นกว่าฉบับดิบ อีก 8 รายการตรงอยู่แล้ว การเทียบภาษาไทยก่อนโดยไม่ตรวจภาษาต้นทางจะนับผิดกับ 2 รายการที่ต้นฉบับเป็นอังกฤษ จึงแก้ auditor ให้เลือก locale ตามต้นทางก่อนนับ

เพิ่มรายชื่อค้นหาเดิมที่ยังไม่ย้ายโดยตรวจ identity และเว้นชื่อสั้น/ชื่อ CS:GO ที่อาจต่าง release 6 ชื่อ ไม่สร้าง alias สำหรับคำถามใหม่เป็นรายประโยค

### รอบ 2: เก็บข้อมูลได้ แต่ยังเลือกช่องตอบไม่ถูก

การทดสอบ 204 เคสแรกผ่าน 198 พบ 6 เคสจาก 3 สาเหตุ: ชื่อเอกสารโดนแปลงเป็นการค้นข้อกฎ, wrongly booked โดน live guard, timezone ถูก FAQ location แย่งตัวตน แก้ precedence ตาม schema และบริบท ไม่แก้ gold ให้ผ่าน รอบถัดไปผ่าน 204/204

ตัวนำเข้าระหว่างพัฒนาพบ taxonomy facet เดิมไม่ตรง enum ใหม่ และ prevalidation อยู่ก่อนใส่ evidence refs แก้ตัวนำเข้าและใช้ candidate แยก เก็บฐานระหว่างทางไว้ ไม่ใช้เป็นผลสุดท้าย

### รอบ 3: ข้อเท็จจริงอยู่ในข้อความรวม แต่ยังไม่อยู่ในช่องเฉพาะ

CPU/RAM/GPU อยู่ใน equipment.usage แต่ specifications มีเพียงโซน/จำนวน จึงเพิ่ม 3 ค่าตรงตาม source ลง specifications พร้อมเก็บ usage เดิม; เพิ่มกรณีทดสอบสเปกไทย/อังกฤษเป็นรวม 206 เคส

พบ source ใหม่มี public_url ว่างแม้ต้นฉบับบอก URL ชัด จึงสร้าง source revision ใหม่ที่อ้าง URL HTTPS เดียวกันจาก lineage ทั้งกลุ่มเท่านั้น ไม่แก้ immutable source เก่า ไม่ใช้ URL แทน approval

ตรวจ ON พบคำถาม timezone ไทยเข้าสู่ semantic entity selector ก่อน typed fallback จึงแก้ให้ schema field ที่ชัดเจนเลือกศูนย์ได้ก่อน นอกจากนี้ FAQ alias “location” เคยกินคำขอช่อง location ของ Parking/Rest seating จนไปเรียกโมเดลโดยไม่จำเป็น แก้เฉพาะ FAQ ที่ตรงกับคำชื่อช่องและมี typed entity ที่ระบุแยกอยู่แล้ว เก็บผลล้ม/transport fail เดิมไว้

เพิ่มช่องชื่อแสดงไทย/อังกฤษของ procedure/contact เพื่อให้หัวข้อเป็นภาษาคนอ่าน ไม่แสดง change_time หรือ URL เป็นชื่อรายการแทน

## เกณฑ์จบงานรอบนี้

- ข้อความฉบับดิบ 31 รายการตรงภาษาต้นฉบับครบ มีอีกภาษาประกอบโดย agent และติดสถานะแปลที่ไม่ได้ owner approve
- ไม่เปลี่ยน 42 offered game IDs / 70 game-service links, ราคา, ตาราง, closure, resource, ปุ่ม และนโยบายที่เก็บอยู่แล้ว
- ทุกช่องที่เพิ่มมีหลักฐานตามไฟล์และ locator ตัวเก่าไม่ถูกลบ
- รายการไม่เติมมีเหตุผลเฉพาะ ระบุสิ่งที่ขาด ไม่กรอกค่าตั้งต้นเพื่อทำให้ผ่าน publication
- คะแนน targeted tests ไม่ถูกใช้แทน full benchmark, live booking oracle, actual LLM inference หรือการตรวจโดยมนุษย์
