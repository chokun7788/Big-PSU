## สิ่งที่ผู้ใช้ต้องการจากบทสนทนานี้

ผู้ใช้กำลังคุยเรื่องเดียวต่อเนื่อง: ขอรายชื่อเกมแข่งขัน → เลือก VALORANT → ขอกติกาของเกมนั้น → ขอกติกาข้ออื่นเพิ่มเติม ไม่ได้เปลี่ยนไปถามกฎทั่วไปของศูนย์ และไม่ควรต้องพิมพ์ชื่อเกมซ้ำทุกข้อความ

หลักฐานคือข้อความและคำตอบในแท็บจริง `http://127.0.0.1:8090/` จำนวน 6 คู่ พร้อม debug ของข้อความสุดท้าย เก็บสำเนาไว้ใน `r36_actual_web_conversation_20261003.txt` และ `r36_actual_web_debug_20261003.txt` โดยไม่ส่งคำถามใหม่

## ทำไมข้อความสุดท้ายจึงตอบแบบนั้น

debug ของ “มีกฏอื่นไหม” ระบุว่า:

- `context_resolution.used_context=false`, `reason=not_followup`, ไม่มี `context_game` และคำถามหลัง resolve ยังเหมือนเดิม
- `competition_rule_query=false`, ไม่มีการล็อกเกม
- ตัวเลือก intent คืน `general/unknown`; คะแนน route หลังขั้น guard อยู่ประมาณ 0.35
- ตัวเลือกคำตอบสูงสุดประมาณ 0.433 อีกตัวประมาณ 0.322 และสถานะ `abstain_low_score` จึงถามให้ผู้ใช้ระบุเรื่องใหม่
- เวลาส่วนใหญ่ของข้อความนี้อยู่ในขั้น intent ของโมเดล ประมาณ 4.584 วินาที จากเวลาตอบรวมที่หน้าเว็บแสดงประมาณ 4.75 วินาที
- `validation.ok=true` หมายถึงคำตอบถามกลับไม่ผิดเงื่อนไขที่ตรวจอยู่ ไม่ใช่หลักฐานว่าเข้าใจความต้องการของผู้ใช้แล้ว

ดังนั้นปัญหาหลักไม่ใช่ไม่มีข้อมูลกติกา แต่เป็นการเสียเป้าหมายเกมก่อนเลือกคำตอบ และการไม่แยกคำขอภาพรวม/ข้อเพิ่มเติมออกจากการค้นหัวข้อเดียว

## จุดเชื่อมประวัติที่ขาด

หน้าเว็บส่งข้อความก่อนหน้า 10 ข้อความ รวม `route_category`, `route_intent`, `resolved_text` อยู่แล้ว แต่ทาง worker ที่ใช้งานจริงไม่ได้ส่ง `recent_history` ต่อจาก server → supervisor → pipeline แม้ pipeline รองรับพารามิเตอร์นี้

ตัว context resolver ได้รับประวัติสำหรับเติมชื่อเกม แต่ตัวสร้างภาพรวมไม่ได้รับประวัติคำตอบ จึงไม่มีข้อมูลว่าข้อกฎใดเพิ่งแสดงไป ปัญหาสองจุดนี้ต้องแก้ร่วมกันจึงจะตอบ “กฎอื่น” ได้ตามเจตนา

## Flow ที่แก้ในรอบนี้

1. แยกคำขอรายชื่อเอกสารการแข่งขันจากคำขอกติกาเกมใดเกมหนึ่ง รองรับถ้อยคำที่ผู้ใช้ถามจริง
2. รับชื่อเกมหลังรายชื่อ/คำถามเลือกเกมเป็นคำขอภาพรวมกติกาของเกมนั้น
3. จับคำขอกฎทั่วไปด้วยรูปแบบที่จำกัด รวม “กฎของเกม” และ “กฎอื่น” ไม่รับตัวเลขปี/ชื่อเกมที่ไม่รู้จัก/คำเนื้อหาเฉพาะที่เหลือเป็นภาพรวมโดยเดา
4. ใช้ระยะการแก้ตัวอักษรสำหรับคำลงท้าย “หน่อย” เมื่อข้อความส่วนก่อนหน้าระบุคำขอกฎชัดเจน เช่น “ขอกฏหนาอย” ไม่แก้ชื่อเกมหรือข้อมูลกติกาด้วยวิธีนี้
5. คำขอกฎที่ไม่มีชื่อเกมใช้เป้าหมายการแข่งขันล่าสุดจากผู้ใช้/คำถามที่ resolve แล้ว สามารถผ่านคำตอบถามกลับหรือคำตอบกฎศูนย์ที่เกิดจากคำขอกฎทั่วไปเดิมได้ แต่หยุดค้นเมื่อผู้ใช้เปลี่ยนเรื่องชัดเจน
6. คำขอภาพรวมเข้าสรุปข้อกฎหลายหมวดจาก rulebook ของเกมเดียว รักษาการตรวจแหล่งข้อมูลและเนื้อหาที่มีอยู่เดิม
7. ส่งประวัติของคำขอนั้นต่อถึง worker และตัวสร้างภาพรวม ไม่มีประวัติรวมข้ามผู้ใช้
8. สำหรับคำขอกฎเพิ่มเติม ใช้คำตอบก่อนหน้าของเกมเดียวเป็นตัวกรองข้อที่แสดงแล้วเท่านั้น ข้อเท็จจริงยังมาจากเอกสาร ไม่ใช้คำตอบเก่าเป็นแหล่งนโยบาย
9. ถ้าไม่เหลือข้อที่ตัวสรุปอ่านได้ ให้บอกข้อจำกัดตรง ๆ ไม่สรุปว่าเอกสารไม่มีกฎอื่น และไม่เติมกฎเอง
10. เพิ่ม log ของภาพรวม: `history_answer_count`, `excluded_clause_count`, `no_further_clauses` เพื่ออธิบายการเลือกข้อเพิ่มเติมครั้งถัดไป

มีคำขอภาษาอังกฤษที่สอดคล้องกันในตัวตรวจร่วมด้วย เช่น more/other/additional rules แต่รอบนี้ไม่ได้ทดสอบผลคำตอบภาษาอังกฤษหรือไทยใหม่

## ไฟล์ที่เปลี่ยน

- `app/pipeline/competition_conversation_signals.py` — ตัวตรวจคำขอรายชื่อ/ภาพรวม/ข้อเพิ่มเติมร่วมกัน
- `app/session/context_resolver.py` — เป้าหมายกติกาและบริบทของคำถามต่อเนื่อง
- `app/pipeline/retrieval.py` — ส่งคำขอภาพรวมไปตัวสรุปหลายหมวด
- `app/pipeline/competition_overview.py` — สรุปข้อเพิ่มเติมโดยกรองข้อที่เคยแสดง พร้อมเหตุผลในผลลัพธ์
- `app/pipeline/engine.py` — ส่งประวัติถึงตัวสรุปและเพิ่ม trace
- `app/web_api/server.py`, `app/web_api/pipeline_supervisor.py` — ส่งประวัติผ่าน worker ของคำขอนั้น

## สถานะที่ตรวจได้ กับสิ่งที่ยังไม่ยืนยัน

ตรวจจากไฟล์/การเริ่มระบบในรอบนี้:

- hash ของไฟล์ข้อมูล/คำตอบอ้างอิงที่ป้องกันไว้ 584 ไฟล์ก่อนและหลังตรงกัน
- สำรองไฟล์ก่อนแก้ รวมไฟล์ที่ Git ยังไม่บันทึก และเก็บ diff ใหม่ ไม่ reset/checkout/commit ทับงานเดิม
- สร้างแพ็กเกจใหม่ `owner_local_delivery_20261003_competition_conversation_r36/PSU_Esports_Chatbot_Local` โดยไม่เขียนทับแพ็กเกจ r35 หรือ log เดิม
- เปิดแพ็กเกจใหม่ที่พอร์ต 8090; launcher PID 2356 และ process ของแพ็กเกจเป็นเจ้าของพอร์ตตามบันทึกเริ่มระบบ
- รักษาแท็บ/ข้อความของผู้ใช้ไว้ ไม่ refresh หน้า เพราะหน้าเว็บเดิมเริ่มประวัติใหม่เมื่อ refresh

ยังไม่ได้ยืนยัน:

- ไม่รัน unit/HTTP/UI/ground truth หรือส่งคำถามใหม่ ตามคำขอหยุดทดสอบก่อนหน้า จึงยังไม่อ้างว่าการตอบชุดบทสนทนานี้ผ่านหลังแก้
- การเข้าใจเจตนาในตารางเป็นการอนุมานจากลำดับการคุยจริง; ผลตอบหลังแก้ยังต้องเห็นจากการใช้งานครั้งถัดไป
- ไม่เปลี่ยนนโยบายกติกาหรือรับรองข้อมูล/คำแปลแทนเจ้าของ และไม่มีการเก็บสถานะจองจริงใหม่ในรอบนี้
- ประวัติที่ใช้ยังจำกัด 10 ข้อความล่าสุดของแท็บเดิม ไม่ใช่การจำบทสนทนาทั้งหมดข้ามการ refresh
