# ขอบเขตรอบทดสอบ R70

## คำขอ

ทดสอบคำถามประมาณครึ่งชุด เฉพาะ Format กลาง และเปิด LLM

## ชุดที่เลือก

- ประชากรเดิม: 20,554 request keys จาก R64/JOBS.jsonl
- เลือก: 10,277 request keys = 50% พอดี
- ทุกเกณฑ์ที่ผูกกับคำถามที่เลือก: 27,923 grades
- locale ที่ระบุ: ไทย 3,922 / อังกฤษ 5,121 / auto 1,234 — auto จะตรวจภาษาอีกครั้งตอนรัน
- แบ่งกลุ่มตาม locale + คลัง + domain + รูปแบบคำถาม เลือกตามสัดส่วนด้วย hash seed ที่บันทึกไว้ ไม่เลือกเฉพาะข้อที่เคยผ่าน
- 484 strata ในประชากร เลือกมา 411 strata กลุ่มเล็กบางกลุ่มไม่ได้รับเลือกเพราะจำกัดไว้ครึ่งชุด จึงไม่อ้างว่าตรวจครบทุกกรณี

## ระบบที่ใช้

- สำเนาแชทใหม่ R69 พร้อมฐาน Format กลาง 602 รายการ
- profile: r69-migration-preview อ่านร่างล่าสุดโดยไม่สร้าง approval/release
- เปิด LLM assistance และ experimental_allow_llm ทั้งรอบ ไม่มีแขน OFF และไม่มีแขน Format เดิม
- ใช้ subprocess 4 ตัวเพื่อประมวลผลชุดตรวจ จำกัดสิทธิ์เรียกโมเดลร่วมกัน 1 ช่อง
- ไม่มี HTTP/browser/load benchmark ในรอบนี้ ประวัติแต่ละคำถามเริ่มใหม่
- Booking ใช้ controlled unavailable เพื่อไม่เอาสถานะสดที่ไม่มี oracle มาให้คะแนนว่าตรงจริง
- เวลาทดสอบคงที่ 2026-10-16 เวลา 12:00 ไทย คำถามที่มี reference_date ใช้วันของตัวเอง

## การเก็บหลักฐาน

- SELECTED_JOBS.jsonl / STRATA.json / CONFIG.json เก็บการเลือกและ source hashes
- full01/RESULTS_*.jsonl.gz เก็บคำตอบจริง route, trace, decision_artifact, sources, grades และ model transport
- full01/PROGRESS.json เป็นสถานะล่าสุดที่ปรับระหว่างรัน ไม่ใช่รายงานสุดท้าย
- full01/RUN_FINISHED.json เกิดเมื่อ worker จบรอบ จากนั้นตัววิเคราะห์ตรวจ key/grade coverage ซ้ำก่อนสร้างรายงาน FINAL
- EARLY/MID เป็น snapshot ผลบางส่วน เก็บไว้ ไม่ใช้แทน FINAL

## วิธีแปลผล

แยก protocol, outcome, evidence identifiers, ข้อความ/รูปแบบ, validation, performance และ grader ออกจากกัน เกณฑ์เดิมไม่ได้ถูกแก้เพื่อลบข้อที่ไม่ผ่าน การตรวจข้อความเพิ่มเติมไม่ใช่คำยืนยันจากเจ้าของ

การเปิด flag LLM ไม่เท่ากับโมเดลทำงานสำเร็จ ต้องเห็น transport/schema ที่ผ่านจริง หากสิทธิ์ socket ปฏิเสธ ให้สรุปว่าไม่ยืนยัน inference ไม่เปลี่ยนเป็น OFF แล้วเรียกว่า ON

ข้อมูลศูนย์ โค้ดแชท R69 และข้อมูลเดิมไม่ถูกแก้ระหว่างรอบนี้ การตรวจสาเหตุเป็นการอ่านผลที่รันแล้ว ไม่รันคำถามเดิมซ้ำเพื่อหาคำตอบที่ดีกว่ามาแทน
