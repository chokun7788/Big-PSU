# R84 แก้การเสนอหัวข้อแก้ไขผิดประเภทและตรวจราคาเหมา

## ขอบเขตและหลักฐาน

R83 ไม่ได้ยืนยันขั้นตอนสลิปให้เอกสารอื่น แต่ยังถามยืนยันหัวข้อสลิปผิดเรื่องเมื่อถามยอดเงินหรือเอกสารตัวตน ใช้ฐาน Format กลาง R78 ที่ติดตั้งจริง และ LLM ON ทดสอบเฉพาะกรณีเกี่ยวข้อง ไม่รัน full test หรือชุดเดิม/OFF

## ขั้นตอน

1. สำรองโค้ดปัจจุบันและ SHA256 ฐานข้อมูลก่อนแก้ เก็บผลเก่าทั้งหมด
2. ตรวจ rental_package ทั้ง 24 รายการ เทียบค่ากับเซลล์ราคาใน workbook ต้นฉบับแบบอ่านอย่างเดียว รวมกลุ่มผู้ใช้และช่วงวัน ไม่ตีความครึ่งวันเป็น 4 ชั่วโมง
3. บันทึกตัวอย่างก่อนแก้จาก candidate ที่ใช้โค้ดปัจจุบัน ผลต้องตรวจหัวข้อ clarification ด้วย ไม่ใช้เพียง HTTP สำเร็จหรือไม่มี facts ผิด
4. แยกวัตถุของงาน correction ด้วยภาษาของหมวด: ยอดเงิน, หลักฐานชำระเงิน, เอกสารตัวตน ใช้ร่วมกับ subjects ที่ประกาศใน format ไม่มี record ID เฉพาะคำถาม
5. ปิดเส้นทางเสนอ/เลือก source ที่มีวัตถุขัดกันทั้ง literal matching, retrieval/model และ fallback menu คำที่ยังจำแนกไม่ได้คงเส้นทางถามยืนยัน ไม่อ้างว่าเข้าใจทุกคำ
6. ข้อมูลวิธีแก้ยอดเงิน/เอกสารตัวตนที่ไม่มีใน source ให้ระบุสิ่งที่ยังไม่ทราบและช่องทางเจ้าหน้าที่ ไม่สร้างเงื่อนไขคืนเงิน/อนุมัติแทนศูนย์
7. ทดสอบ unit ของขอบเขต, clarification, qualified reply และ source revisions ที่เกี่ยวข้อง ตรวจเส้นทาง LLM จริงและเว็บจริงแยกกัน
8. ติดตั้งเฉพาะไฟล์ที่ผ่าน โดยตรวจ hash ไม่เปลี่ยนก่อนเขียน ตรวจฐานข้อมูล/strict binding/compact opening และไฟล์อื่นไม่เปลี่ยน
9. รายงานผล/ข้อจำกัด ราคาใน workbook ไม่เท่ากับยืนยันราคา ณ วันนี้ ไม่แก้ validity หรือ approvals เอง

## ทบทวน 3 รอบก่อนลงมือ

1. ตรวจทุกเส้นทาง: แก้เฉพาะ prompt ไม่พอ เพราะ fast menu และ fallback ไม่ต้องเรียกโมเดล ต้องใช้ guard ร่วมกัน
2. ตรวจอนาคต: derive จาก subjects ของ profile แทนผูก source ID รองรับ profile ใหม่ในหมวดเดิม เกณฑ์ใหม่เป็นเพียงข้อห้ามจับคู่ขัดกัน ไม่อนุญาต facts เอง
3. ตรวจการวัดผล: negative case ต้องไม่เห็นแม้แต่เมนูสลิปผิดเรื่อง การแสดงเพจศูนย์เป็นการติดต่อสำหรับ unknown ไม่ใช่หลักฐานว่าผิด procedure เสมอ ทดสอบราคาเทียบ source เป็นอิสระจากคำตอบ

## ปรับจากผลทดสอบจริง

- Baseline เปิด LLM 15/26 ผ่าน: 8 ข้อ correction ผิดหัวข้อ และ 3 ข้อราคาเหมาตี scope ผิด ไม่ใช่ราคาใน DB หาย
- Candidate 1 ผ่าน 21/26: guard เฉพาะ profile ยังไม่พอ โมเดลเลือก FAQ ปกติที่เป็นข้อมูลเอกสารเช็กอิน หรือ FAQ สลิปที่ซ้ำในแหล่งเดิมได้ ต้องจัดการ known-unconfirmed need ก่อนเลือก semantic near-neighbour เมื่อยังไม่มี source ที่ระบุชัด
- ราคาเหมา: เลื่อน operation rental ให้มาก่อน how-much ทั่วไป, จับ internal/external organization/unit/agency ด้วย grammar และ map เฉพาะ audience ที่ source ประกาศว่าเป็นหน่วยงาน, จับทุกโซนกับรายการ zone All Zones ที่มีจริง ไม่มี hardcode rate IDs
- Candidate 2 ผ่าน 26/26 เป็นเป้าหมายชุดเดียวกับ baseline ไม่มี model transport error ระหว่าง 26 ข้อ แต่ยังต้องแยกผลผ่านเว็บจริงหลังติดตั้ง
