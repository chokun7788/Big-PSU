# ทดลองชุดแก้ R72

1. เปิด `Open-New-Chat.cmd` ในโฟลเดอร์นี้
2. แชทจะเปิดที่ `http://127.0.0.1:8103/` และแสดงป้าย R72
3. จบการใช้งานเปิด `Stop-New-Chat.cmd`

ชุดนี้เป็นสำเนาพัฒนา format กลาง เปิด LLM ตามค่าเริ่มต้น ใช้ฐานข้อมูลของตัวเอง 602 รายการ และเก็บ log/state ใน `runtime` ของโฟลเดอร์นี้

ใช้ Python ที่มีอยู่ในโฟลเดอร์ข้างกัน `PSU_Esports_Chat_New_R69/runtime/python` จึงไม่ต้องคัดลอก runtime ซ้ำ ชุดนี้ยังไม่ใช่แพ็กเกจ portable สำหรับส่งเครื่องอื่น ต้องเก็บ R69 ไว้ข้างกันและมี Ollama/โมเดลตามระบบเดิม

หากต้องแก้ร่างข้อมูลของ R72 ใช้ `Open-Data-Editor.cmd` (พอร์ต 8104) การบันทึกร่างไม่ใช่การอนุมัติหรือเผยแพร่จริง

## ตัวอย่างตรวจอาการที่แก้

- `จ่ายค่าจองยังไง` → วิธีโอนและสลิปจากข้อมูลเดิม
- `แล้วเมื่อไหร่` → กำหนดชำระจากบริบทก่อนหน้า
- `How many sessions can one booking include and how do I pay?` → จำนวนรอบและวิธีชำระ
- `กฎศูนย์มีอะไรบ้าง` → กฎศูนย์ ไม่ใช่รายการเกม
- `What genre is God of War Ragnarök?` → อ่าน genre ผ่านคู่ระเบียนที่ตรวจหลักฐานแล้ว
- `วันหยุดราชการเปิดมั้ย` → ขอวันที่ให้ชัดก่อนเช็กวันปิดพิเศษ

## หลักฐานการตรวจ

อ่าน `FLOW_R72_TH.md` และ `REPORT_R72_TH.md` ผลทั้งหมดแยกใน `results` / `verification` เก็บคำตอบและ trace ของแต่ละรอบไว้

การตรวจอัตโนมัติในรอบนี้ใช้ตัวรับ HTTP จริงแบบ connection ใน memory และ dispatcher จริง แต่สิทธิ์เครือข่ายของเครื่องมือยังไม่ให้ยืนยันการเรียกโมเดลจริงหรือ browser/TCP ได้ จึงต้องตรวจบน Windows ปกติอีกครั้งก่อนรับรอง production

ถ้าต้องกลับ R69 ให้ปิด R72 ด้วยตัวหยุดของ R72 แล้วเปิดทางลัด R69 เดิม ข้อมูลของสองสำเนาเป็นคนละฐาน ถ้าแก้ข้อมูลผ่าน editor ต้องเลือกสำเนาที่ต้องการให้ตรง
