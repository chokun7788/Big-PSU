# ตรวจ WinError 10013 จาก Windows ปกติ

## ผลที่ตรวจผ่านเครื่องมือแล้ว

- พบไฟล์ ollama.exe ที่ติดตั้งอยู่ แต่การพบไฟล์ยังไม่ยืนยันว่าบริการกำลังรัน
- อ่านรายการพอร์ตผ่าน Get-NetTCPConnection ไม่ได้: Access to a CIM resource was not available to the client จึงไม่ถือว่าพอร์ตไม่มีบริการ
- PowerShell ผ่านเครื่องมือเรียก Ollama 11434 และ R78 8115 แล้วได้ forbidden by its access permissions ทั้งสองจุด
- ขอสิทธิ์ network ผ่านระบบแล้ว ได้ network=null ไม่มีสิทธิ์เพิ่ม
- หลักฐานอยู่ TOOL_NETWORK_PROBES.json และ LOCAL_INVENTORY.json

ผลนี้ยังไม่ได้เปรียบเทียบกับ PowerShell/โปรแกรมที่คุณเปิดจาก Windows ปกติจริง ๆ จึงยังระบุไม่ได้แน่นอนว่าเป็น sandbox ของเครื่องมือหรือส่วนความปลอดภัยอื่น

## วิธีตรวจจากฝั่งคุณ

1. เปิดโฟลเดอร์นี้ผ่าน File Explorer แล้วดับเบิลคลิก **Open-Connection-Check.cmd** ไม่ต้องเปิดแบบ Administrator
2. ตัวตรวจจะอ่านรายการพอร์ต เรียกรายชื่อโมเดล และถ้ามีโมเดลที่แชทใช้อยู่ จะลองสร้างคำตอบสั้น ๆ หนึ่งครั้ง ไม่ดาวน์โหลดโมเดล
3. ถ้า R78 เปิดอยู่และตรวจ identity ตรง จะถามแชท 3 ข้อใน session ใหม่เพื่อตรวจคำถามต่อ ระบบแชทจะเก็บประวัติ session ใหม่นี้ตามปกติ
4. ผลอยู่ **user_results/<วันเวลาและรหัสรอบ>/** เก็บแต่ละรอบแยก ไม่มีการทับผลเก่า บอกในแชทว่า “รันตัวตรวจแล้ว” แล้วผมจะอ่านผลจากโฟลเดอร์นี้ต่อได้

ถ้าบริการไม่ได้เปิด ตัวตรวจจะรายงานตามที่ตรวจได้:

- พอร์ต 11434 ไม่มี listener: เปิดโปรแกรม Ollama ที่ติดตั้งอยู่ แล้วตรวจใหม่
- พอร์ต 8115 ไม่มี listener: เปิด Open-New-Chat.cmd ในโฟลเดอร์ r78_web_session_check_20261016 แล้วตรวจใหม่

การสร้างคำตอบโมเดลอาจรอได้ถึง 60 วินาที และแต่ละคำถามแชทไม่เกิน 45 วินาที ถ้าหมดเวลา จะเก็บว่า timeout ไม่สรุปว่าโมเดลตอบผิด

## อ่านผลอย่างไร

| ผล | แปลว่า |
|---|---|
| ฝั่งคุณเชื่อมได้ แต่เครื่องมือถูกปฏิเสธ | สองบริบทมีสิทธิ์/สภาพแวดล้อมต่างกัน ยังไม่ระบุว่า security component ใดเป็นต้นเหตุ |
| ทั้งสองฝั่งได้ 10013/permission denied | ตรวจ log การบล็อกและสิทธิ์โปรแกรมต่อ ไม่ควรรีบสรุปว่าเป็น firewall ตัวใด |
| รายการพอร์ตอ่านได้สำเร็จและไม่มี listener | ในขณะที่ตรวจ ยังไม่มีบริการเปิดรอที่พอร์ตนั้น |
| api/tags ผ่าน แต่ generate ไม่ผ่าน | บริการเข้าถึงได้ แต่การสร้างคำตอบยังต้องตรวจ model/error/timeout |
| generate ผ่าน แต่แชทไม่ผ่าน | ตรวจเว็บ identity, API, session และ log แชทต่อ |
| ทั้งหมดผ่าน | การเชื่อมต่อ/คำตอบตัวอย่างผ่าน ยังไม่ใช่การรับรองคำตอบทุกหมวด |

ตัวตรวจไม่เปลี่ยน firewall/antivirus/สิทธิ์เครื่อง ไม่ติดตั้งหรือดาวน์โหลดโมเดล ไม่เริ่ม/หยุดบริการเอง และไม่เปิดพอร์ตออกเครือข่ายภายนอก

ไฟล์ผลอาจมีชื่อโมเดล รายละเอียดฮาร์ดแวร์ตามที่ health API แสดง และคำตอบแชทตัวอย่าง ควรเก็บไว้ในเครื่องสำหรับตรวจ ไม่จำเป็นต้องส่งออกสาธารณะ
