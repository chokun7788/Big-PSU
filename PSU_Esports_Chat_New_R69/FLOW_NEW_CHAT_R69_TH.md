# Flow แชทใหม่ R69

## 1. ขอบเขตการย้าย

R68 candidate06 → สำรองผ่าน SQLite backup → ฐานแชทใหม่ และ seed ที่เก็บแยก

ตรวจทุกตารางเทียบเชิงเนื้อหา ไม่ตรวจเพียงจำนวนรายการหรือชื่อเกม ไฟล์โค้ดและฐาน R68 เป็นแหล่งอ่านเท่านั้น โครงการ Downloads ไม่ถูกแก้

## 2. เปิดแชท

เปิดตัวเปิด → เลือก Python และฐานภายในชุดนี้ → ตรวจพอร์ตและตัวตน → เริ่มเซิร์ฟเวอร์ที่ localhost → เตรียมตัวประมวลผล 2 ตัวและคิว → ตรวจ health ว่าเป็นชุดนี้จริง → เปิดหน้าเว็บ

health ล้มเหลวต้องแสดงข้อผิดพลาด ห้ามถือว่าการมี PID เท่ากับพร้อมใช้ log แต่ละรอบใช้ชื่อใหม่ ตัวหยุดตรวจตัวตนและ token ของชุดนี้ก่อนหยุด

## 3. รับคำถาม

คำถาม + ภาษา + รหัสบทสนทนา → ตรวจข้อความและคำขอซ้ำ → คิว/ขีดจำกัดงาน → อ่านประวัติที่เซิร์ฟเวอร์เก็บ → ส่งคำถามต้นฉบับและ common_read_state เข้า CommonAnswerer

สำหรับ profile นี้ ไม่ให้ตัวแก้ประวัติของฐานเก่าเขียนคำถามแทนก่อนเข้าฐานกลาง กรองงานนอกขอบเขตศูนย์ตามเดิม

## 4. เลือกและประกอบคำตอบ

1. คำทักทาย/แนะนำตัวใช้ข้อความเกี่ยวกับหน้าที่ผู้ช่วย
2. อ่าน snapshot ของหัวฉบับล่าสุด แหล่งข้อมูล และ epoch ภายในธุรกรรมอ่านเดียว
3. หารายการ เลือกช่อง ตรวจความสัมพันธ์ เช่น เกม–บริการ–อุปกรณ์–กลุ่มราคา
4. หากต้องใช้ LLM ให้เสนอเฉพาะช่อง schema ภายใต้งบเวลา แล้วตรวจผล ห้ามให้แต่งข้อเท็จจริงแทนฐาน
5. ประกอบเฉพาะค่าที่มีหลักฐาน เก็บสิ่งไม่ทราบและเงื่อนไขไว้ ตรวจเนื้อหาที่เลือกและการอ้างอิง
6. หากตัวตรวจปฏิเสธคำตอบ ให้ขอรายละเอียดเพิ่ม เก็บเหตุผลของ candidate ที่ถูกปฏิเสธไว้ในผลวิเคราะห์
7. หากไม่มีคำตอบจากฐานและเป็นการถามสถานะสด ให้ใช้ตัวเชื่อมสถานะ WordPress ซึ่งอ่านอย่างเดียว
8. หากยืนยันสถานะสดไม่ได้ ให้แจ้งว่ายืนยันไม่ได้ ห้ามใช้จำนวนเครื่องหรือเวลาเปิดเป็นหลักฐานว่าเครื่องว่าง
9. หากไม่ตรงรายการ ให้ขอชื่อ/หัวข้อเพิ่ม ห้ามย้อนกลับไปตอบจาก FAQ ราคา หรือ RAG ของฐานเก่า

ทุกผลในเส้นทางฐานใหม่ระบุ profile, draft_preview_only และ legacy_fallback_used เพื่อใช้แยกตรวจ

## 5. ตอบและบันทึก

ส่งข้อความและแหล่งข้อมูล → เก็บ common_read_state ที่สอดคล้องกับคำตอบ → บันทึกประวัติ/ผลวิเคราะห์เฉพาะ R69 → แสดงคำตอบและเวลา หน้าเว็บมีแถบสถานะข้อมูลที่ย้ายแสดงอยู่เสมอ

## 6. เจ้าของเพิ่มหรือแก้

หน้ากรอก → ตรวจ schema/ความสัมพันธ์/ที่มา → บันทึก revision ใหม่และเพิ่ม epoch → คำถามถัดไปอ่านข้อมูลล่าสุด → ทดสอบไทย/อังกฤษและการถามต่อ → ตรวจข้อเท็จจริง/แปล/วันมีผล → กระบวนการอนุมัติและเผยแพร่จริงภายหลัง

แชทชุดนี้เลือกอ่านร่างล่าสุดอย่างเปิดเผย ปุ่มเผยแพร่ของตัวแก้ข้อมูลไม่ได้เปลี่ยนให้แชทนี้กลายเป็น profile production โดยอัตโนมัติ

## 7. เกณฑ์ตรวจและข้อจำกัด

- การย้าย: เนื้อหาทุกตารางตรงกับ R68 และไม่มีการสร้าง approvals/release
- คำตอบ: ตรวจข้อความที่ต้องปรากฏ/ต้องไม่ปรากฏ ทั้งไทย อังกฤษ และถามต่อ
- การแก้ไข: ทดสอบเพิ่มและแก้ในฐานแยก เก็บฉบับเก่าและตรวจว่าไม่ตอบค่าที่หมดอายุหลังแก้
- การทำงาน: ตรวจ worker จริงและภาษาที่ตอบ แยกจากการเรียก HTTP/เบราว์เซอร์
- LLM: แยกเปิด flag / เรียก transport สำเร็จ / schema ผ่าน / ตอบถูกต้อง ออกจากกัน
- จอง: แยก fixture ที่รู้ผล / เข้าถึง WordPress / ความตรงกับสถานะจริง ออกจากกัน
- ติดข้อจำกัดใดให้บันทึกตามที่ตรวจได้ ห้ามสรุปว่าผ่าน production จากผลบางเส้นทาง
