# ผลการย้ายข้อมูลเข้าแชทแยก R69

วันที่ตรวจ: 16 ตุลาคม 2026 — เวลาไทย

## 1. สิ่งที่ทำเสร็จ

- สร้างโฟลเดอร์ `PSU_Esports_Chat_New_R69` พร้อม Python ของตัวเอง หน้าแชท และตัวเปิด/หยุด ไม่พึ่งโฟลเดอร์ runtime R58 ในการเปิดชุดนี้อีก
- นำฐาน R68 `candidate06.sqlite` มาเป็น `system/data/knowledge/common.sqlite` ด้วย SQLite backup และเก็บฐานตั้งต้นแยกเป็น `seed_R68_preserved.sqlite`
- เชื่อมหน้าแชทธรรมดากับข้อมูล Format กลางจริง ใช้ร่างล่าสุดอย่างเปิดเผย ไม่ใช่การเปลี่ยนค่า DB แล้วปล่อยให้เส้นทางเก่าเลือกคำตอบจากอีกฐาน
- ตัวแก้ข้อมูลกับแชทอ่านฐานใหม่เดียวกัน การเพิ่ม/แก้ revision สะท้อนในการถามครั้งถัดไปโดยไม่ต้องแก้คำตอบในโค้ด
- แยกประวัติ คิวงาน และ log ของชุดใหม่ ตัวเปิดสร้างชื่อ log ใหม่แต่ละรอบ
- เปิด LLM assistance เป็นค่าเริ่มต้น แต่ไม่คัดลอก/ดาวน์โหลดโมเดล และไม่อนุญาตให้โมเดลแต่งข้อเท็จจริงแทนข้อมูลกลาง
- เก็บตัวเชื่อมสถานะ WordPress ที่อ่านอย่างเดียวไว้สำหรับคำถามสถานะสด

**สถานะ:** ย้ายและเชื่อมเส้นทางแชทแล้ว แต่ยังเป็นชุดตรวจข้อมูลก่อนเผยแพร่ ไม่มีการรับรองโดยเจ้าของหรือยืนยันการใช้งานผ่านเบราว์เซอร์จริงในรอบนี้

## 2. หลักฐานว่าข้อมูลไม่หายระหว่าง R68 → R69

หลักฐาน: `verification/delivery02/RESULTS.json`

- ฐานต้นทาง R68, seed และฐานแชทใหม่มีเนื้อหา **ตรงกันทุกตารางเชิงตรรกะ** รวม revisions, sources และ audit ไม่ใช่ตรวจเพียงหัวรายการ
- หัวรายการที่ใช้อยู่ **602 รายการ / 21 หมวดที่มีข้อมูล** ตัวฟอร์มรองรับ 24 หมวด โดย game_mode, news และ live_binding ยังไม่มีข้อมูลจริง
- 51 ระเบียนเกมไม่เท่ากับจำนวนเกมที่เปิดให้บริการจริง รายการที่ให้เล่นใช้ความสัมพันธ์ game_service เดิม 70 รายการ ต้องไม่ประกาศว่าให้เล่นทั้งหมด 51 เกมเพียงเพราะมีระเบียนเกม
- ราคา 24, ราคาเหมา 24, controls 43, schedule 7, closure 3, competition 4, competition_rule 104, FAQ 190 และบุคลากร 25 อยู่ในฐานใหม่
- approvals = **0** และ active release = **ว่าง** ตรงต้นทาง ไม่สร้างการอนุมัติหรือเผยแพร่เอง
- seed มี SHA-256 ตรง baseline ที่เก็บก่อนเชื่อมระบบ
- ตรวจ hash ไฟล์โค้ดต้นทาง R68 **386 ไฟล์: ไม่เปลี่ยน** โครงการเดิมใน Downloads ไม่ถูกเขียนในรอบนี้

ความครบข้อนี้หมายถึง “สำเนาตรงกับ R68” ไม่ใช่ “ทุกความรู้เก่าได้รับการยืนยันแล้ว” รายการที่ R68 กันไว้ยังถูกกันไว้ เช่น aliases กำกวม 6 ชื่อ, Overcooked raw control variants 4 แถว และ fact cards กติกา 166 รายการที่ยังไม่ใช่ verified missing facts รายละเอียดและเหตุผลอยู่ในรายงาน R68 เดิม

### ตัวอย่างเนื้อหาที่ตรวจ

- คำทักทายสะกดผิด `สวัาดี`
- รายการเกม PS5 17 เกมและ PC 6 เกม โดยไม่เอาเกมของโซนอื่นมาปน
- คำบรรยาย Animal Crossing ฉบับเต็มทั้งสองภาษา รวมข้อความท้ายที่เคยตกหล่น
- สเปก PC CPU/RAM/GPU ที่มีหลักฐาน
- `กฏตอนเเข่ง cs2 มีอะไรมั่ง` และ TEKKEN 8 เรื่องข้อพิพาท ไม่ตอบกติกา VALORANT แทน
- ที่จอดรถภาษาอังกฤษ และขั้นตอนแก้จองผิดเครื่อง
- ถามต่อ PC → PS5, ราคา General Adult → ศิษย์เก่า, ปุ่ม eFootball → R2
- คำถามนอกขอบเขต และคำถาม Steam/ความรับผิด/คืนเงินที่ยังยืนยันสถานการณ์เฉพาะไม่ได้
- fixture เครื่องว่าง/ไม่ว่าง และ fixture ที่ข้อมูลสดเข้าถึงไม่ได้

## 4. ข้อผิดพลาดที่พบและการแก้

### 4.1 อ่านฐานไม่ได้แม้คัดข้อมูลครบ

รอบ api_off01 ผ่าน 19/38 เพราะ view ใหม่เริ่ม SQLite transaction ซ้ำกับ CommonStore.connect ซึ่งเริ่มให้อยู่แล้ว จึงล้มก่อนอ่านเนื้อหา แก้เฉพาะ adapter ในชุดใหม่ให้ใช้ transaction เดียว ตรวจซ้ำแล้วอ่านได้ ไม่แก้ข้อมูลเพื่อกลบข้อผิดพลาด

### 4.2 ได้คำตอบบางส่วน แต่เงื่อนไขเฉพาะยังไม่ได้รับการยืนยัน

คำถาม “ลืมออกจาก Steam ศูนย์รับผิดชอบคืนเงินทั้งหมดไหม” ดึงกฎคืนเงินทั่วไปมา แม้ตัวตรวจระบุว่าคำถามยังมีส่วนไม่ครอบคลุม รอบ api_off02 จึงพบ validation failure

แก้ให้ dispatcher ไม่ส่ง candidate ที่ validation ปฏิเสธเป็นคำตอบยืนยัน ให้ขอรายละเอียดเพิ่ม และเก็บ mode/validation_errors/query_plan ของ candidate ที่ปฏิเสธไว้ใน decision_artifact เพื่อวิเคราะห์ต่อ โดยไม่แต่งนโยบาย Steam ใหม่

ข้อจำกัด: การขอรายละเอียดเพิ่มป้องกันคำตอบเกินหลักฐาน แต่ยังไม่ทำให้ข้อมูลที่ขาดกลายเป็นข้อมูลที่รู้ ต้องมีข้อเท็จจริงเพิ่มจึงจะตอบสถานการณ์นั้นได้ครบ

### 4.3 ตัวตรวจทดสอบคาดคำผิด ทั้งที่คำตอบถูก

- fixture PC2 ไม่ว่างตอบ “not available for the full period 10:00-11:00” ถูกต้อง แต่ oracle เดิมบังคับต้องมีคำว่า “booked” จึงแก้เกณฑ์ให้ตรวจความหมายและเวลา ไม่เปลี่ยน renderer ที่ตอบถูก
- update01 ตรวจเฉพาะ prefix `HTTP/1.1 200` ทั้งที่ handler ใช้ `HTTP/1.0 200` จึงรายงานผิด 4 จุดแม้เนื้อหาถูก แก้ให้ตรวจเลขสถานะ HTTP แล้ว update02 ผ่าน

ผลและ log ก่อนแก้ยังอยู่ใน verification ไม่ทับไฟล์เดิม

### 4.4 ภาษาอังกฤษหายที่ขอบเขต subprocess

เมื่อเรียก worker โดยมี locale='en' แต่ไม่มี locale_decision supervisor แปลง None เป็น {} ตัวแปลง mapping สร้างค่าเริ่มต้นภาษาไทยและทับภาษาอังกฤษ

แก้สำเนา supervisor ใน R69 ให้คง None เพื่อให้ worker resolve จาก locale/คำถามตามปกติ เพิ่มการตรวจ effective_language แล้ว workers02 ตอบไทย/อังกฤษตรงที่ขอทั้งสองงานพร้อมกัน

workers01 ตรวจแค่ชื่อเกม จึงเคยผ่านแม้ภาษาผิด ไม่ใช้ผลนั้นอ้างว่าภาษาอังกฤษผ่าน

## 5. สิ่งที่ยังติดสภาพแวดล้อม

### การเปิดเว็บจริง

ลองตัวเปิดใหม่แล้ว แต่การเรียก localhost/health ถูกปฏิเสธสิทธิ์ socket การลองรันเซิร์ฟเวอร์ตรงแสดงว่า listener เริ่มได้ ขณะที่ HTTP client ในสภาพแวดล้อมผู้ช่วยยังล้มด้วย **PermissionError / WinError 10013**

จึงสรุปได้ว่า “ยังยืนยันการเชื่อมต่อ HTTP ผ่านสภาพแวดล้อมนี้ไม่ได้” ไม่สรุปว่าโค้ด bind พอร์ตไม่ได้ทั้งหมด หรือว่าเว็บใช้งานจริงผ่านแล้ว หลังตรวจหยุด session เซิร์ฟเวอร์ที่เปิดโดยตรงแล้ว

ตัวเปิดไม่เปิดหน้าเว็บหาก health ยังไม่ผ่าน ตัวหยุดไม่กล่าวว่าหยุดแล้วหาก process ยังอยู่แต่ตรวจการเชื่อมต่อไม่ได้ ให้ผู้ใช้เปิด Open-New-Chat.cmd จาก Windows โดยตรงเพื่อใช้และยืนยันเส้นทางเบราว์เซอร์ต่อ

### LLM

api_on01 มี planner attempt 1 ครั้ง: **transport_ok=false, schema_accepted=false, error_stage=transport, error_type=URLError** คำตอบที่ผ่านมาจากเส้นทางอ่านข้อมูลที่ไม่ต้องสร้างเนื้อหาด้วยโมเดล ไม่ใช่หลักฐานว่า LLM แปลหรืออนุมานถูกแล้ว

### สถานะจองจริง

การตรวจว่าง/ไม่ว่างรอบนี้ใช้ fixture ที่รู้ผล ตัวเชื่อม WordPress เดิมถูกเก็บไว้ แต่ไม่ได้ดึงและเทียบกับรายการจองจริงใหม่ การที่ผู้ใช้เคยยืนยันสถานะจริงในอดีตไม่ถูกนำมาอ้างเป็นผลทดสอบ WordPress รอบนี้

## 6. ก่อนเผยแพร่จริงยังต้องทำอะไร

1. เปิดแชทจาก Windows และตรวจการใช้งาน browser → คิว → API → worker → ตอบกลับ/หยุดจริง
2. ตรวจการเข้าถึงบริการโมเดลที่ติดตั้งในเครื่อง และแยก transport/schema/content ตามเดิม
3. ตรวจ WordPress สดในสภาพแวดล้อมใช้งานจริง โดยคงรายการที่รู้ผลเพื่อเทียบว่าง/ไม่ว่าง
4. เจ้าของตรวจนโยบายที่ขัดกัน วันมีผล และคำแปลที่ยังไม่อนุมัติ ตามรายการใน docs/OWNER_CONFIRMATION_REQUIRED_R67_TH.md
5. ใช้กระบวนการเผยแพร่ที่อ่าน approved release โดยชัดเจนก่อนเปิดสาธารณะ แชท R69 นี้ยังอ่านร่างล่าสุดและผูก localhost ตามวัตถุประสงค์ตรวจชุดย้าย
