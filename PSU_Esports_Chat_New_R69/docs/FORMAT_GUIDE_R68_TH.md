# คู่มือช่องข้อมูลเพิ่มเติม R68

ใช้ candidate06.sqlite หรือ DELIVERY_final/candidate.sqlite เท่านั้น เปิดทดลองร่างด้วย Open-R68-Drafts.cmd พอร์ต 8100 ต้องมี runtime ของ r58 อยู่ข้างโฟลเดอร์นี้ ผลยังไม่ใช่ production release และยังไม่เปลี่ยนเว็บเดิม

## ช่องใหม่และช่องที่คืนข้อมูล

- เกม: official_description เก็บข้อความฉบับเต็ม; description_captured_at เป็นเวลาจับข้อมูล; description_scope_note เก็บข้อจำกัด แยกจาก summary ที่เป็นคำอธิบายสั้น
- เกม: venue_zone_ids เลือกโซนของศูนย์ตามไฟล์ inventory; supported_platforms ใช้ความเข้ากันได้ทั่วไปของเกม ห้ามใช้สองช่องนี้แทนกัน
- บริการ: inventory_verified_on และ inventory_basis ใช้ระบุที่มา/วันที่ของรายการเกมและเครื่อง ไม่ใช่ผลว่างหรือถูกจองสด
- อุปกรณ์: device_type ใช้จัดประเภท; specifications มี key/value/unit เช่น CPU / Intel Core i5-14400 / null ส่วนคำแนะนำใช้งานเก็บใน usage ตามเดิม
- การแข่งขัน: source_title ใช้ชื่อหัวเอกสารจริง; division ใช้เฉพาะที่ระบุจริง เช่น ประเภททีมชาย; facet เป็นหมวดค้นหาจากฉบับเก่า ไม่ใช่การรับรองความครบของกติกา
- ติดต่อ/ขั้นตอน: name เป็นชื่อแสดงไทยและอังกฤษ; contact.value เป็นลิงก์จริง ส่วน procedure.topic เป็นรหัสหัวข้อภายในและ steps เป็นลำดับให้ผู้ใช้ทำ

## ตัวอย่างแก้ข้อมูลเดิม

1. ค้นหาเกม/บริการเดิม แล้วเลือกแก้รายการเดิม ไม่ตั้งรหัสใหม่สำหรับการแก้คำบรรยาย
2. กรอกช่องที่ทราบตามแหล่งต้นฉบับ ใส่ source และ locator; ไม่ทราบจำนวนผู้เล่น วันมีผล หรือตัวตนเครื่อง ให้เก็บ unknown
3. ถ้าเกมเป็นคนละภาค/edition ให้แยกรายการ อย่าเพิ่มเป็น alias ของอีกภาค
4. ใช้หน้า “ทดลองร่าง” ถามทั้งไทยและอังกฤษ แล้วตรวจข้อความปลายคำตอบและเงื่อนไข ไม่ตรวจแค่มีชื่อเกม
5. บันทึก revision และผ่านขั้นตอนตรวจ/เผยแพร่เดิมก่อนเปลี่ยนข้อมูล production
