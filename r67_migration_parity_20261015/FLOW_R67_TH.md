# R67 — ตรวจการย้ายและทำให้ Format กลางอ่านข้อมูลเดิมได้ครบ

## เป้าหมายและขอบเขต

รักษาข้อมูลเดิมและ revision/source/approval ทั้งหมด ทำในฐานสำเนาและโค้ดแยกใน workspace ตรวจแหล่งจริงก่อนย้าย ไม่ใช้ log หรือ Ground Truth เป็นข้อเท็จจริง ไม่สร้างวันมีผล นโยบาย การกดปุ่ม หรือ owner approval ขึ้นเอง ทดสอบ common เท่านั้น ไม่รัน legacy/full 20,554 ซ้ำ

## ขั้นตอน

1. Snapshot ไฟล์จากโปรเจกต์จริงพร้อม SHA256 และสำเนาฐาน R66 ก่อนแก้
2. ตรวจ canonical 270 รายการทุกชนิด ทุกช่องข้อความ TH/EN พร้อมตรวจ lineage เดิม 1,933 ช่องจากแหล่งอื่นด้วย แยกข้อมูลที่ใช้ตอบออกจาก routing/refusal configuration
3. ทำตาราง source → record → field → row → locale ไม่ใช้จำนวนรายการหรือ schema pass แทนความครบเชิงเนื้อหา
4. เพิ่ม optional fields สำหรับข้อมูลเดิมที่ไม่มีช่อง: สังกัด/วาระบุคลากร หมายเหตุบริการ สรุปชุดปุ่ม ชื่อหัวเอกสาร ลำดับข้อความ และหลายหัวข้อในกฎ
5. ย้ายปุ่มเป็น structured bindings: เก็บชื่อปุ่มเดิมและรายการปุ่มแยก action/notes/section/order; gesture/context ที่ไม่ได้ระบุคง unknown ไม่บังคับ known ทั้งแถวหรือทิ้งคำอธิบาย
6. เก็บ semantic intent เดิมเป็น metadata ใน FAQ และใช้ concept lookup ร่วมกัน หลักฐานคำตอบยังมาจาก answer ของ source; ไม่เปลี่ยน refusal template เป็นข้อเท็จจริง
7. ตรวจข้อมูลตกหล่น/ความต่างกับต้นฉบับทุกช่อง แยก exact, การแปลที่ปรับไว้แล้ว, ไม่พบช่องที่อ่านได้ และ configuration ที่เก็บไว้
8. ทดสอบคำถามจากแหล่งข้อมูลเองทั้ง TH/EN พร้อมกรณีขอบเขต: ปุ่มเดี่ยว/ทั้งหมด แพลตฟอร์มผิด หมายเหตุรายบริการ สังกัดบุคลากร กฎหลายหัวข้อ ราคา/อายุข้อมูล และคำถามต่อเนื่อง ใช้ off/on LLM แยกกัน
9. อ่าน failures จริงก่อนปรับ ไม่ปรับ gold/source ให้คะแนนผ่าน เก็บแต่ละ iteration ไว้ ทดสอบซ้ำเฉพาะความเสี่ยงที่เปลี่ยน
10. แพ็กโค้ดและฐานร่างพร้อมคู่มือเปิด preview, รายงาน coverage, ประเด็นที่ต้องขอ facts และผลทดสอบที่ยังไม่ผ่าน ตรวจ hash ก่อนนำไปใช้กับโปรเจกต์จริง

## ปรับระหว่างทำตามหลักฐานจริง

- ขยาย inventory ไปไฟล์ก่อน canonical export พบคำบรรยายจาก Our Games 31 รายการ และผังปุ่มเพิ่มเติม 21 แถว ต้องตรวจ raw sources เพิ่มจากการตรวจ canonical และ lineage เดิม
- เก็บ original button_label เพื่อรักษาเครื่องหมาย / แยกจาก buttons array และไม่ตีความว่าเป็น simultaneous
- เพิ่ม source_coverage/verification_note และแปลคำอธิบายให้ผู้ใช้เข้าใจ รักษาข้อจำกัดของแหล่งต้นทาง
- เพิ่ม read-only evidence access ใน Owner DraftView เพราะการทดสอบหน้าเจ้าของกับข้อมูลจริงพบ AttributeError ที่ direct harness ไม่พบ
- เพิ่มการสืบ field ตาม schema เมื่อเปลี่ยน entity แบบสั้น ตรวจคำตอบต้องมีเนื้อหาที่ถาม ไม่ยอมให้แค่ชื่อ entity ผ่าน และตรวจ validation ด้วย
- ปรับ oracle ที่เดาว่าบุคคลภายนอกเท่ากับ General Adult ออก ไม่แก้นโยบายกลุ่มผู้ใช้ให้ผ่านตัวทดสอบที่ตั้งสมมติฐานผิด
- คำขอสิทธิ์ network และเขียน ROOT ได้ grant ว่าง จึงหยุดเฉพาะการเรียก socket/การนำเข้าจริง เก็บโค้ด ฐานร่าง คู่มือ และรายงานที่ตรวจได้ไว้ครบใน workspace

## ทบทวนแผน 3 รอบ

- รอบ 1: ตรวจจำนวน record อย่างเดียวไม่พอ → เพิ่ม source-field/locale/row coverage และ lineage เดิม
- รอบ 2: การแตก buttons array ทำให้ '/' หายและอาจเข้าใจเป็นกดพร้อมกัน → เก็บ original button_label, gesture unknown และ notes เดิม
- รอบ 3: เก็บข้อมูลครบไม่ได้รับรองการตอบ → เพิ่มคำถามจาก source อิสระจากตัวแปลง ตรวจเนื้อหาและ scope; schema/transport/protocol/owner approval แยกกัน

## เกณฑ์รายงาน

Coverage ต้องระบุ denominator และขอบเขตว่าครอบคลุม canonical fields หรือ original lineage ห้ามบอกว่าทุกข้อเท็จจริงของทุกไฟล์ถูกต้องเพราะ snapshot ครบ ช่องแปลที่แก้ไขโดย agent ไม่ใช่ owner verification โค้ดและฐานใน workspace ไม่เท่ากับเว็บที่เปิดอยู่ใช้รุ่นนี้แล้ว
