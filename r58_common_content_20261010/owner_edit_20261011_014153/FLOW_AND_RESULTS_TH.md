# เพิ่มการแก้ไขข้อมูลเดิม — 11 ตุลาคม 2026

## Flow ที่ลงมือทำ

เลือกหมวด → เลือกรายการเดิม → อ่านฉบับล่าสุดและฉบับที่เผยแพร่ → แก้เฉพาะช่อง → เปรียบเทียบก่อน/หลัง → ระบุเหตุผล → ตรวจแหล่งข้อมูลและคำแปล → บันทึกร่าง revision ใหม่ → อนุมัติ revision/hash นั้น → ตรวจวันที่มีผล → เผยแพร่แบบ transaction → คำถามใหม่อ่าน release ใหม่

ประวัติอ่านจาก revisions และ audit เดิม ผ่าน API ที่ต้องมี token เช่นเดียวกับ API เจ้าของอื่น การเปิดประวัติไม่แก้ head, approval หรือ release ทุกการแก้ต้องใช้ expected_version เพื่อไม่ทับร่างใหม่ที่ผู้อื่นบันทึกแล้ว

## รอบตรวจและปรับ

1. เพิ่มหน้าการแก้ไข ประวัติ เหตุผล และตารางก่อน/หลัง ใช้ระบบ revision เดิม ไม่สร้างฐานใหม่หรือย้ายข้อมูลเจ้าของ
2. พบตัวกันการเผยแพร่ในอนาคตกว้างเกินไป กระทบการตรวจราคาอนาคตที่ติดกัน จึงจำกัดให้กันกรณีแทนฉบับที่มีผลอยู่ตอนนี้ ทดสอบขอบเวลาเริ่มมีผลและราคาเหลื่อมกัน
3. พบคำถามทดสอบราคาเรียกชื่อที่ fixture ไม่มีชื่อจริง จึงเปลี่ยนเป็นคำถามชื่อกลุ่มผู้ใช้ที่มีอยู่จริง ไม่แก้ production routing เพื่อรองรับชื่อ fixture
4. ตรวจหน้าเว็บพบตารางแสดงชื่อย่อและวันที่ว่าเปลี่ยนทั้งที่ความหมายเดิม สาเหตุเป็นลำดับ key ของ object กับรูปแบบ timestamp จึงเทียบ object โดยเรียง key และเทียบเวลาเป็น instant เดียวกัน หลังแก้ตารางราคาแสดงเพียงช่องราคา และตารางเกมแสดงเพียงวิธีเล่น

## ผลอัตโนมัติ

- ชุด focused 36 รายการ: รอบสองผ่าน 35 รายการ อีกหนึ่งรายการเป็นคำถาม fixture ที่ไม่มีชื่อ; แก้คำถามแล้วรันรายการนั้นซ้ำผ่าน จึงมีหลักฐานผ่านครบ 36 รายการที่ไม่ซ้ำกัน ไม่ใช่ผลจากการรันทุกชุดใหญ่
- ครอบคลุมราคา เกม นโยบาย กฎการแข่งขัน ฉบับเก่า immutable ร่างไม่รั่วสู่ release การอนุมัติฉบับเก่า conflict การแก้ภาษาอังกฤษต้องทบทวนใหม่ API history ต้องยืนยันตัวตน และการอ่าน history ไม่เปลี่ยน epoch
- กันการเผยแพร่ฉบับอนาคตแทนราคาที่ใช้ปัจจุบัน และอนุญาตเมื่อถึงเวลาเริ่มจริงใน fixture ที่ควบคุมนาฬิกา
- owner.js ตรวจ syntax และตรวจ DOM/การคลิกผ่านเว็บจริงบนฐานจำลองแยก
- หน้าเว็บ: ราคา 35 → 70 เปรียบเทียบเฉพาะราคา; บันทึกเป็นฉบับ 2 แต่ preview อังกฤษยังตอบ 35; ประวัติฉบับ 1 แสดง 35; หลังอนุมัติและเผยแพร่ preview อังกฤษตอบ 70 และสถานะระบุแชทใช้ฉบับ 2
- หน้าเว็บ: แก้วิธีเล่นไทย/อังกฤษในเกมเดิม แสดงความต่างเพียงช่องวิธีเล่น และบันทึกเป็นร่างได้

## ข้อจำกัดและสิ่งที่ยังต้องยืนยันโดยเจ้าของ

- ราคา/ข้อความตัวอย่างเป็น fixture ไม่ได้ยืนยันราคาหรือนโยบายใหม่จริงของศูนย์
- ยังต้องให้เจ้าของตรวจข้อมูลใหม่ แหล่งประกาศ วันที่มีผล และความหมายคำแปลตามจริง
- ยังไม่มีการตั้งเวลาเผยแพร่อัตโนมัติ ต้องเผยแพร่เมื่อถึงวันที่เริ่มใช้
- ประวัติหน้าจออ่านอย่างเดียว แสดงล่าสุด 50 ฉบับ ไม่ใช่เครื่องมือคืนค่าอัตโนมัติหรือแก้หลายรายการพร้อมกัน
- ไม่ได้รัน Ground Truth 20,000 กว่ารายการหรือการทดสอบสถานะ WordPress สดในงานนี้
- พอร์ต 8100 ถูก Windows ปฏิเสธ จึงตรวจด้วยพอร์ตว่างแบบสุ่มบน 127.0.0.1; ไม่ได้เปลี่ยนพอร์ตบริการจริง
