# สถานะส่งมอบ R82

สร้างตัวรันอัตโนมัติ `Open-Automatic-LLM-Test.cmd` แล้ว รองรับตรวจ/เปิด Ollama ที่ติดตั้ง ตรวจ/เปิดหรือโหลด R78 ใหม่เมื่อโค้ดเก่า เปิด LLM ตาม launcher เดิม ตรวจการสร้างข้อความจากโมเดลจริง และทดสอบผ่าน HTTP 14 ข้อความจากชุด R81 พร้อมสรุปผลเอง

## ตรวจแล้ว

- `RUNNER_QA_final.json`: 22/22 ข้อตรวจ ผ่านด้วย controlled fixtures ครอบคลุม permission denied, ไม่มีบริการ, เปิดบริการ, รีสตาร์ตโค้ดเก่า, ไม่หยุดแอปอื่น, ไม่ดาวน์โหลดโมเดล, แยก inference/schema/content และ syntax
- `RUNNER_QA.json`: รอบต้น 18/18 เก็บไว้เดิม
- การทดสอบข้างต้นไม่เรียกโมเดลหรือเครือข่ายจริง และไม่เริ่ม/หยุดบริการจริง
- สร้างเป็นโฟลเดอร์ใหม่ ไม่แก้ R78/R81 หรือฐานข้อมูลราคา/นโยบาย

## ข้อจำกัดของการสั่งจากแชท

ขอสิทธิ์ network ผ่านระบบในเทิร์นนี้แล้ว ผลที่ได้รับคือ `permissions.network = null`, `scope = turn` จึงยังไม่มีสิทธิ์เพิ่มสำหรับเรียกบริการในเครื่องโดยตรง ผลการเชื่อมต่อเครื่องมือที่เคยยืนยัน WinError 10013 อยู่ใน `r79_connection_diagnostics_20261017/TOOL_NETWORK_PROBES.json`

ไม่ได้รันตัวช่วยอัตโนมัติจากเครื่องมือเพื่อพยายามหลีกเลี่ยงสิทธิ์ ตัวช่วยหยุดทันทีหากพบ permission denied ก่อนเปิดหรือรีสตาร์ตบริการ ไม่เปลี่ยน firewall/สิทธิ์ระบบ ไม่ลองช่องทางอื่น

## ยังรอผลจริง

ให้ผู้ใช้เปิด `Open-Automatic-LLM-Test.cmd` จาก Windows หนึ่งครั้ง หลังจากนั้นตัวรันทำขั้นตอนที่เหลือเองและเก็บผลใต้ `results/<timestamp-id>` ไม่มีการเทสเต็ม corpus ในรอบนี้

การเปิด LLM ไม่ได้แปลว่าทุกคำถามต้องเรียก LLM คำถามที่ตอบจากข้อมูลตรงหรือจำเป็นต้องยืนยันหัวข้ออาจข้ามโมเดลตาม Flow จริง ตัวรันนับการเรียก selector จริงและความล้มเหลวแยกจากผลคำตอบเสมอ ส่วนการทดสอบ READY เป็นการยืนยันโมเดลและ warm-up เท่านั้น ไม่ใช่การทดสอบความแม่นยำเลือกข้อมูล
