## ผลทดสอบช่วงขอบและวันปิด

ใช้บริการจำลองที่ไม่มีรายการจอง ทดสอบ 11:59, 12:00, 12:30, 13:00 และ 16:00 ในวันจันทร์ อังคาร ศุกร์ และวันที่บันทึกปิดพิเศษ 28 ก.ค. 2026 รวม **20 กรณี × ไทย/อังกฤษ** ผลก่อนแก้พบว่า Dashboard API ให้ Slot 12:00–13:00 เป็น `available` ในวันจันทร์ อังคาร และศุกร์ ขณะที่ปฏิทินบริการให้ `outside_hours`. วันที่ 28 ก.ค. แชทบอทบันทึกว่าปิด แต่ Dashboard ซึ่งยังไม่มี `dates` override ใช้ตารางอังคารปกติ

หลังแก้ เมื่อคำตอบจองสดจาก Dashboard อ้างว่าช่วงที่ถามเปิด แต่ปฏิทินบริการที่บันทึกไว้ไม่รองรับ แชทบอท **ไม่ยืนยันว่าจองได้หรือว่าง** ทั้งไทยและอังกฤษ และระบุว่าข้อมูลขัดกัน ผลตรวจครบ 20 กรณีอยู่ใน `p0_boundary_matrix_20260926.json`. การจำลองวันที่ Admin ปิดเฉพาะวันยังทำให้ Dashboard ปิด Slot ตามที่กรอก แต่ทางตอบตารางประจำของแชทบอทยังไม่รู้วันปิดนั้น; ดู `p0_date_override_20260926.json`

## โค้ดที่แก้ในโปรเจกต์จริง

- `app/calendar/service_calendar.py`: อ่านวันที่ ISO `YYYY-MM-DD` เพื่อให้คำถามวันที่ชัดเจนตรวจวันปิดที่บันทึกไว้ได้
- `app/pipeline/bilingual_english.py`: คำถามอังกฤษที่ระบุวันที่แบบ `DD/MM/YYYY` หรือ ISO ใช้ปฏิทินวันนั้น ไม่กลับไปตอบตารางทั่วไป; เปลี่ยนหมายเหตุให้ชัดว่าวันหยุดไทยอย่างเดียวไม่ได้ปิดศูนย์อัตโนมัติ
- `app/runtime/fast_answer.py`: ปรับหมายเหตุภาษาไทยในหลักเดียวกัน และแยก mode กรณีข้อมูล Dashboard ขัดกับปฏิทิน
- `app/booking/live_status.py`: ไม่ยอมรับ payload ที่ไม่มีสถานะศูนย์หรือไม่มีรายการบริการว่าเป็นหลักฐานสถานะสด; ตรวจวันที่ที่ Dashboard ส่งกลับก่อน; เมื่อแหล่งเวลา/วันปิดขัดกันตอบว่ายังยืนยันไม่ได้; คำถาม “ตอนนี้เล่นได้ไหม” ภาษาไทยเข้าทางตรวจสดเช่นเดียวกับอังกฤษ
- เพิ่ม `tests/test_p0_calendar_booking_reconciliation_20260925.py` สำหรับกรณีที่แก้

ไม่ได้เปลี่ยนนโยบาย เวลาในไฟล์ของเจ้าของ หรือข้อมูลวันปิดที่กรอกไว้ ZIP `2026.09.25-owner-review-candidate` เดิมยังไม่รวมโค้ดรอบนี้

## แยกผลเชื่อม API กับความถูกต้องของสถานะ

| การตรวจ | ผล | ขอบเขตของหลักฐาน |
|---|---|---|
| Local Dashboard API `127.0.0.1:8091` วันที่ตรวจรอบนี้ | เชื่อมต่อไม่ได้ (`WinError 10061`) | ยังไม่มีผลสถานะสดของเจ้าของในรอบนี้; `p0_api_probe_20260926.json` |
| HTTP บน loopback ที่เสิร์ฟ aggregate fixture จำลอง | เชื่อมสำเร็จ, ได้วันที่และ resource ที่ร้องขอ; คำตอบจอง/ว่าง 4/4 ตรงเฉลย fixture | พิสูจน์ทาง HTTP ของ adapter โดยใช้เซิร์ฟเวอร์จำลอง **ไม่ใช่** Dashboard หรือ WordPress จริง; `p0_http_fixture_20260926.json` |
| Fixture CSV ที่กำหนดผลคาดหวังจากแถวจองล่วงหน้า | สถานะ 4/4 Slot และคำตอบไทย/อังกฤษ 6/6 ตรงผลคาดหวัง; aggregate payload ไม่เผยชื่อใน fixture | เป็นข้อมูลจำลอง ไม่ใช่ independent oracle ของเจ้าของ; `p0_booking_fixture_20260926.json` |
| Payload ที่ติด `source=remote_csv_live` แต่ไม่มีบริการ | หลังแก้ถูกปฏิเสธว่าไม่มีรายการบริการที่ใช้ยืนยันได้ | HTTP/CSV fetch สำเร็จเพียงอย่างเดียวไม่เท่ากับข้อมูลบริการครบ |
| Unit/regression tests | **76/76 ผ่าน**; English date-aware smoke test ผ่าน | ทดสอบโค้ดและ fixture ไม่ใช่การรับรองสถานะ WordPress จริง; `p0_unittest_20260926.txt` |

ยังพบกรณี VR 30 นาที: booking fixture 09:00–09:30 ทำให้ Dashboard นับทั้งช่อง 09:00–10:00 ว่าถูกจอง และคำตอบ 09:30–10:00 เป็น 0/1 ว่าง ตามช่วงรายการจองเพียงอย่างเดียวครึ่งชั่วโมงหลังไม่ทับกัน แต่ **ยังไม่ทราบว่า WordPress อนุญาตให้จองครึ่งชั่วโมงหลังแยกหรือไม่** จึงยังไม่แก้ตรรกะนี้โดยเดานโยบาย

## คำถามที่ต้องให้เจ้าของศูนย์ตอบ

1. **12:00–13:00 จองหรือเล่นได้จริงหรือเป็นพักเที่ยงทุกวัน?** รวมวันที่ Admin เปิดพิเศษด้วยหรือไม่ และ `open_periods` ใน Dashboard หมายถึงเวลาเปิดอาคารหรือ Slot ที่ลูกค้าจองได้?
2. **วันปิดพิเศษให้ไฟล์ใดเป็นหลัก?** ให้ Admin Dashboard `dates` หรือ `data/calendar/service_closures.jsonl` เป็นแหล่งเดียวและซิงก์กันหรือไม่? หากสองไฟล์ขัดกัน อันใดชนะ? วันที่ 28–30 ก.ค. 2026 ที่อยู่ในไฟล์แชทบอทยังเป็นวันปิดที่เจ้าของรับรองหรือไม่?
3. **VR ที่จอง 09:00–09:30 สามารถจอง 09:30–10:00 แยกได้หรือไม่?** หากได้ ควรแสดง/คำนวณ Slot 30 นาที; หากไม่ได้ โปรดระบุกฎขั้นต่ำของ VR ให้ชัด
4. **ขอ snapshot จองที่ลบข้อมูลส่วนบุคคลแล้วหนึ่งวันที่เจ้าของรู้ผลจริง**: service ID/ชื่อบริการ, เวลาเริ่ม–สิ้นสุด, สถานะจอง, เวลา/แฮชของ CSV export และเฉลยว่า PC, PS5, Nintendo, Cockpit, VR ช่องใดว่างหรือถูกจอง รวมกรณียกเลิกและ no-show ถ้ามี โดยไม่ส่งชื่อ เบอร์ อีเมล หรือ booking token

จนกว่าจะได้คำตอบข้างต้น ผลรอบนี้รับรองได้เพียงตรรกะบน fixture และการไม่อ้างความว่างเมื่อหลักฐานขัดกัน ยังรับรองความถูกต้องรายช่องจากระบบเจ้าของหรือความพร้อมเปิดใช้งานสาธารณะไม่ได้
