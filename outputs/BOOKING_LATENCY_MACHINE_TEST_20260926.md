# ผลวัดเวลา Chatbot ดึงสถานะจองบนเครื่องนี้ — 26 ก.ย. 2026

ทดสอบด้วยแพ็กเกจ r3 โดยเปิด Dashboard และ Chatbot ชั่วคราวบนพอร์ต 8095/8096 แล้วส่งคำถามผ่าน `/api/chat` เหมือนหน้าเว็บ ใช้ข้อมูล CSV จริงจาก WordPress; endpoint ระบุ `source=remote_csv_live` และ `privacy=aggregate_only` ไม่บันทึกข้อมูลผู้จองในผลทดสอบ ปิดบริการทดสอบทั้งสองตัวหลังวัดเสร็จ

| คำถาม | ดึงตรงจาก Dashboard | คำถามแรกหลังเปิด Chatbot | ถามซ้ำภายในแคช 10 วินาที | ถามใหม่หลังแคชหมด |
|---|---:|---:|---:|---:|
| 28 ก.ย. 10:00 PC1 (Maintenance เช้าวันจันทร์) | 1,313 ms | 4,701 ms | 106 ms | 957 ms |
| 29 ก.ย. 10:00 PC1 (ช่วงเปิดตามตาราง) | 1,870 ms | 4,320 ms | 132 ms | 1,141 ms |

รอบ 29 ก.ย. Chatbot ตอบว่า `PC #01 (1 Person) ว่างตลอดช่วง 10:00-11:00` จากไฟล์ export ที่ดึงได้จริง แต่ยังไม่มีผลที่เจ้าของตรวจจากระบบจองเพื่อยืนยันว่าความว่างนั้นถูกต้อง รอบ 28 ก.ย. ตอบว่าไม่เปิดให้จองในช่วง Maintenance ซึ่งตรงกับตารางในไฟล์ศูนย์

**การตีความ:** เมื่อระบบทำงานอยู่แล้วและต้องดึงใหม่ เวลาที่วัดได้ราว **1 วินาที** ในสองรอบนี้ คำถามแรกหลังเริ่ม Chatbot ใช้ราว **4–5 วินาที** เพราะมีค่าเริ่มต้นของกระบวนการตอบ ถามซ้ำในแคชใช้ราว **0.1 วินาที** ตัวเลขเป็นตัวอย่างบนเครื่องและเครือข่าย ณ เวลาทดสอบ ไม่ใช่การรับประกันทุกครั้ง

การทดสอบนี้ปิด startup warmup, LLM preflight และ worker supervisor เพื่อเปิดบริการชั่วคราวโดยไม่แตะ log ของโปรเจกต์ เส้นทางตอบสถานะจองและค่าแคช 10 วินาทีใช้โค้ดเดียวกับแพ็กเกจจริง ดังนั้นเวลาของการใช้งานผ่าน launcher ปกติอาจต่างออกไปเล็กน้อย ไฟล์ CSV ที่ดึงสำเร็จอาจยังช้ากว่าการเปลี่ยนแปลงบน WordPress จริง; ยังไม่ได้วัดเวลาหน่วงของการ export หลังจอง/ยกเลิก
