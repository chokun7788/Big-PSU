# วิเคราะห์ข้อมูลบริการ 50 ข้อ — r48 / 2026-10-08

## สรุปข้อมูล

- ยืนยันจากคำตอบผู้ใช้ 19 ข้อ → 18 claims (ที่อยู่ข้อ 5–6 ซ้ำกัน)
- เว้นคำตอบ 28 ข้อ; ข้อ 45–46 มีคำตอบแต่ต้องแยกขอบเขต; ข้อ 47 ยังไม่ตอบนโยบายเพราะผู้ใช้ไม่เข้าใจคำถาม
- บันทึกต้นฉบับและคำตอบภาษาอังกฤษเป็นไฟล์ใหม่ ไม่ทับ log/ข้อมูลเจ้าของเดิม ภาษาอังกฤษเป็นคำแปลของผู้ช่วย ยังไม่ใช่การตรวจรับคำแปลโดยเจ้าของ
- กฎมาสายอ้างข้อความที่บันทึกอยู่ก่อนรอบนี้ ไม่ใช่นโยบายที่ผู้ใช้ยืนยันใหม่ และไม่ยืนยันว่ามีข้อยกเว้น 15 นาที

## ผ่านการทดสอบอัตโนมัติ

- เว็บเดิมผ่านเนื้อหา 6/36 ของคำถามที่มีคำตอบชัดชุดนี้ (ไม่ใช่คะแนนทุกความสามารถของระบบ)
- รุ่นใหม่ r48.2 เว็บจริง 136/136 เคส ไทย 68 / อังกฤษ 68; ตรวจ claim/เงื่อนไข/ภาษา/ส่วนที่ขาด พร้อม HTTP และ timeout รวมการเก็บข้อยกเว้นคืนเงินเดิมในคำตอบ
- regression เว็บที่เกี่ยวข้อง 25/25 เคส รวม 29 requests (ทดสอบ r48.1 ก่อนเพิ่มข้อความข้อยกเว้นคืนเงินใน r48.2); location oracle เปลี่ยนเฉพาะที่อยู่ใหม่ซึ่งผู้ใช้เพิ่มอาคาร 5 ชั้น 1 และใช้ source ชุดใหม่นี้ ส่วนผล/เกณฑ์ r47 เดิมเก็บไว้
- unit 52 methods จาก 4 ไฟล์ ผ่านทั้งหมด; unit subtests ตรวจ scope/ต้นทาง/เงื่อนไขเพิ่มเติม
- source ↔ release hash ตรง 167/167; ไฟล์ข้อมูลเดิมและ rules เดิมคงเดิม
- เวลาตอบชุดเว็บนี้ median 0.427s, สูงสุด 1.999s เป็นคำตอบ fact/missing แบบเจาะจง ไม่ใช่ benchmark WordPress สดหรือทุกคำถามของระบบ

**คำว่าเคสผ่านในส่วนที่ไม่มีคำตอบหมายถึงระบบบอกว่าขาดนโยบายใดได้ถูกต้อง ยังไม่ได้เติมนโยบายแทนเจ้าของ และไม่ได้แปลว่าทั้ง 50 ข้อมีคำตอบครบแล้ว**

## สาเหตุที่พบและแก้

1. ข้อมูลใหม่ยังไม่อยู่ในเส้นทางเลือกคำตอบ จึงได้ no_answer/ถามกลับหรือคำตอบจากคนละหมวด เพิ่ม facts พร้อม source binding ก่อนตัวเลือกทั่วไป
2. การจับคำกว้างนำ “เล่น/เวลา/คน” ไปเลือกรายการอุปกรณ์หรือตารางเปิด แม้ถามมาสาย ต่อเวลา เด็ก หรือเวลาอัปเดต เพิ่มการตรวจ condition และ missing fields ที่เฉพาะกับคำถาม
3. ข้อมูลใกล้เคียงมีคนละขอบเขต: wrong slip ≠ overpayment; รวมหลายเครื่อง ≠ บัญชีคนอื่น; แสดงบัตร ≠ ชื่อตรงบัตร; public access ≠ guardian permission จึงไม่อนุมาน policy ข้ามเงื่อนไข
4. ระหว่างแก้พบ English inflections และ synonym เงินคืน/คืนเงิน ที่ตรวจไม่เจอ; เพิ่มการจับรูปคำและ unit ตามข้อผิดพลาดจริง
5. ตัวตรวจช่วงแรกใช้ “ไม่ได้” ตรงตัว แต่คำตอบจริง “ไม่สามารถ…ได้” มีความหมายปฏิเสธถูกต้อง แก้ oracle ตรวจปฏิเสธทั้งสองรูปโดยคงเงื่อนไขรายชื่อผู้จอง; ไม่แก้คำตอบเพื่อไล่คะแนน
6. ใช้ source ID ของกฎมาสายกับ registry ที่ไม่มี ID นั้นทำให้ source probe ล้ม แก้ด้วย hit จาก rule เดิมและเก็บ recorded_rule_ids; ผล run ที่ล้มเก็บไว้
7. ตรวจข้อมูลซ้ำพบกฎคืนเงินเดิมใช้ตอบบางส่วนของเครื่องขัดข้อง/ศูนย์ปิดได้ จึงเพิ่มใน r48.2 และบอกว่ายังไม่มีขั้นตอนหรือจำนวนเวลาชดเชย ไม่เหมารวมว่าทุกการปิดพิเศษคืนเงินอัตโนมัติ

## ยังต้องเสริมด้วยงานพัฒนา

- สำนวนและคำผิดนอกชุดนี้ยังไม่รับรองครอบคลุมทั้งหมด โดยเฉพาะ follow-up สั้นที่ไม่มีหัวข้อ เช่น “แล้วมอเตอร์ไซค์ล่ะ” ต้องเพิ่ม memory contract จาก claims ก่อนอ้างว่ารองรับสมบูรณ์
- ยังไม่ได้ยืนยัน multiplayer รายเกมจากการเล่นจริง หรือเวอร์ชันเกมบนเครื่องจริง
- ข้อมูลนี้ไม่บอกค่าจอด จำนวนที่จอดว่าง ค่า spectator หรือข้อยกเว้นราคา ไม่ควรอ้างว่าฟรีจากคำว่าอนุญาตเข้าดู
- source handler ใช้รูปคำ/แนวคิดพร้อมขอบเขต ไม่ใช่โมเดลที่เข้าใจสำนวนได้ไม่จำกัด; ถ้าแก้ถ้อยคำใหม่ต้องทดสอบ false positives กับกฎแข่งขัน/ราคา/เกมด้วย
- structured JSON ถูกใช้โดยตัวตอบไทย/อังกฤษโดยตรง ยังไม่เพิ่มข้อความนโยบายนี้ลงทุก legacy RAG index เพราะจะทำให้ข้อความหลุด scope ได้ งานรวม index ต้องรักษา provenance/เงื่อนไขเดียวกัน
- รุ่นเว็บทดสอบใหม่อยู่ในโฟลเดอร์ release รอบนี้ แพ็กเกจแจกคนอื่นรุ่นก่อนหน้ายังต้อง rebuild ถ้าต้องการส่งพร้อมข้อมูลใหม่
