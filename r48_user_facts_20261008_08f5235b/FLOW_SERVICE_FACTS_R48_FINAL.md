# Flow เพิ่มข้อมูลบริการจากผู้ใช้ — r48 / 2026-10-08

## เป้าหมายและเกณฑ์

ตอบคำถามบริการด้วยข้อเท็จจริงที่ระบุชัดในข้อมูล 50 ข้อ พร้อมรักษาคำตอบเดิม ไฟล์ที่ Git ยังไม่ได้บันทึก และ log เดิม คำตอบที่เว้นไว้ยังไม่ใช่นโยบายอนุญาตหรือห้าม เกณฑ์ผ่านรวมเนื้อหา เงื่อนไข แหล่งข้อมูล ภาษา และการบอกส่วนที่ยังขาด ไม่ใช่เพียง HTTP 200

## ลำดับการทำงาน

1. เก็บต้นฉบับทั้ง 50 ข้อในไฟล์ใหม่ รวมคำผิดและช่องว่างคำตอบ; snapshot ไฟล์เดิมและ hash ก่อนแก้
2. แยก 19 ข้อที่ผู้ใช้ตอบชัดเป็น 18 claims เพราะข้อ 5–6 เป็นที่อยู่เดียวกัน; 28 ข้อไม่ตอบ; 45–46 รอขอบเขต; 47 ต้องอธิบายคำถาม
3. บันทึกแต่ละ claim พร้อมหมายเลขต้นทาง ภาษาต้นฉบับ ภาษาอังกฤษที่ผู้ช่วยแปล และสถานะ ไม่แทนข้อความต้นฉบับ
4. ตรวจการใช้ข้อมูลร่วมกันแบบมีเงื่อนไข: ใช้ที่อยู่เดียวกันกับข้อ 5–6; ขั้นตอนยกเลิก/จองใหม่กับข้อ 18–19; เพจเป็นช่องทางแจ้งทั่วไปกับข้อ 21/26 ได้ แต่ไม่ยืนยันผลแก้ปัญหา
5. แยกบริบทบริการปกติจากกฎการแข่งขันและราคาเหมา; ห้ามนำข้อ 27 ไปทับกติกาอุปกรณ์ในการแข่งขัน
6. เพิ่มตัวตอบจาก structured facts ก่อนเลือกคำตอบทั่วไป ใช้แนวคิดของคำถาม ไม่เก็บทุกประโยคเป็น alias; ไม่ผ่าน LLM เพื่อสร้างนโยบายใหม่
7. ตรวจคำขยายและกรณีย่อย: ฟรี/ทันที/ระหว่างเล่น/จ่ายแล้ว/คืนเงิน/ฝนตก/ผู้ปกครอง/บัญชีเพื่อน มีข้อมูลหรือไม่
8. ถ้า known บางส่วน ตอบส่วนที่รู้และบอก missing_fields; ถ้าไม่มีนโยบาย ตอบว่าต้องยืนยันเรื่องใดอย่างเจาะจง ไม่เปลี่ยนไปตอบอุปกรณ์/เวลาเปิด/รายชื่อเกม
9. กรณีมาสาย เครื่องขัดข้อง และศูนย์ปิด ใช้ข้อความจากกฎการจอง/คืนเงินเดิมแยกแหล่งข้อมูลและบอกส่วนที่ยังขาด; ไม่อ้างว่ากฎเดิมเป็นคำตอบใหม่ของผู้ใช้ ไม่สรุปว่าทุกการปิดพิเศษมีสิทธิ์คืนเงินอัตโนมัติ
10. บันทึก trace: claim_ids / source_items / missing_fields / recorded_rule_ids / translation status / outcome; .98 เป็นความเชื่อมั่นของเส้นทาง heuristic ไม่ใช่การรับรองว่ารู้ทุกนโยบายหรือข้อมูลสด
11. ทดสอบข้อความจริง สำนวนใหม่ ไทย/อังกฤษ และกรณีที่ห้ามอนุมาน; ข้อที่ยังไม่มีนโยบายผ่านเมื่อบอกขอบเขตขาดได้ ไม่ใช่ผ่านเพราะตอบได้ทุกนโยบาย
12. แก้จากข้อผิดพลาดที่มีหลักฐาน เก็บ raw/summary ของแต่ละรอบเป็นชื่อใหม่ ไม่เขียนทับผลเก่า
13. freeze รุ่นใหม่จากรุ่นก่อนพร้อม data ใหม่ ตรวจ hash ตรงกับ source และ restart เฉพาะ server ของ candidate ที่ตรวจรุ่น/PID/parent ได้
14. ทดสอบ HTTP เว็บจริงอีกครั้งและ regression ที่เกี่ยวข้อง; ไม่รัน full 20,000 เคส และไม่ดำเนินการจอง/ยกเลิก/ส่งข้อความเพจจริง
15. ส่งรายงานแยก automated tests จากนโยบายที่เจ้าของยังไม่ตอบ และเก็บประเด็น follow-up สั้น/คำผิดนอกชุดทดสอบเป็นงานต่อยอด

## การตรวจทานและปรับ flow จากสิ่งที่พบจริง

### รอบข้อมูลและต้นทาง

รักษาเงื่อนไข OR ในรายการบัตร, ผู้เล่นที่อยู่ในรายชื่อ, Note สำหรับโอนรวม, ข้อห้ามอุปกรณ์เฉพาะคีย์บอร์ด/เมาส์; ไม่เปลี่ยนเป็นกฎเข้มกว่าหรือกว้างกว่าเดิม ภาษาอังกฤษแปลจากคำตอบไทยที่ผู้ใช้ยืนยัน ยังไม่ได้มีเจ้าของตรวจคำแปลแยก

### รอบคำถามใหม่และขอบเขต

เพิ่ม explicit missing สำหรับรอรอบ/ค่าจอด/ทันที/สลับเครื่อง/การอัปเดต/ผู้ปกครอง/บัญชีเพื่อน; แก้การจับ “คนเล่น” ที่ไปตีความคำถามจำนวนที่นั่งเป็นสิทธิ์ใช้แทนผู้จอง และแยก map เกมจากแผนที่ศูนย์

### รอบหลักฐานการทดสอบ

พบและแก้ “เงินคืน” ไม่เข้ากฎ “คืนเงิน”, machines ไม่ตรง machine, crashes ไม่ตรง crash, counting ไม่ตรง count และ source ID ของกฎเดิมไม่ได้อยู่ใน registry ใหม่ จึงบันทึก hit จาก rule เดิมตามต้นทางอย่างชัดเจน ผลรอบที่ล้มเหลวยังคงเก็บไว้

## สิ่งที่ยังต้องยืนยัน

ข้อ 45 เป็นข้อยกเว้นเฉพาะ “เลือกวันผิดและจ่ายแล้ว” ใช่ไหม? ใครดำเนินการ ต้องติดต่อเพจหรือกดยกเลิก/จองใหม่ และเงื่อนไขเวลาก่อนรอบเป็นอย่างไร? ข้อ 46 ห้ามเลื่อนวันแทนคืนเงินในกรณีใด?

ข้อ 47 หมายถึงลูกค้าจองแล้ว แต่ศูนย์ประกาศปิดพิเศษทีหลัง: ศูนย์ย้ายวัน คืนเงิน หรือให้ลูกค้าเลือก? ทำผ่านช่องทางใด?

ส่วน blank อื่นไม่กำหนดค่าตอบแทน อนุญาต อายุขั้นต่ำ หรือข้อยกเว้นแทนเจ้าของ รายการคำถามเจ้าของในรายงาน 50 ข้อใช้จัดลำดับถามต่อได้
