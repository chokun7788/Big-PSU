# อัปเดตเฉพาะ Flow เก่า เป็น r57.4

**ส่ง ZIP อัปเดตนี้ไฟล์เดียวให้ผู้ที่มีชุดเก่าครบแล้ว** ไม่ต้องส่งชุดโมเดลหลาย GB อีก
ใช้กับโฟลเดอร์ Ready วันที่ 3 ตุลาคม, ZIP 01/02 วันที่ 3 ตุลาคม และชุด R50 ที่ตรวจเทียบไว้
ชุด R56 ที่ manifest เป็น r57.4 อยู่แล้วจะตรวจและข้ามไฟล์ที่ตรงกัน

1. แตก ZIP นี้ก่อน ห้ามเปิดตัวอัปเดตจากใน ZIP
2. ที่โฟลเดอร์แชทเก่า เปิด `Stop-Chatbot.cmd` แล้วรอหยุด หากไม่ได้เปิดแชทอยู่ ข้ามขั้นตอนนี้ได้
3. เปิด `Update-Old-Flow.cmd` ในโฟลเดอร์อัปเดต ถ้าถามตำแหน่ง ให้เลือกโฟลเดอร์แชทเก่าที่มี `Start-Chatbot.cmd`, `runtime`, `system`
4. รอข้อความ Done แล้วเปิด `Start-Chatbot.cmd` จากโฟลเดอร์แชทเก่าตามเดิม

## อะไรเปลี่ยน / อะไรคงเดิม

| ส่วน | ต้องส่งใหม่ไหม |
|---|---|
| โค้ด Flow เก่าและเว็บที่เปลี่ยน | มีเฉพาะไฟล์ที่ต้องอัปเดตใน ZIP นี้ |
| ข้อมูลอ้างอิงที่ปรับภายหลัง | อัปเดตเฉพาะไฟล์ชุดเดิมที่ตรวจ hash ตรง; ถ้าปลายทางแก้เองจะหยุดก่อนทับ |
| ตัวเปิด/ตัวหยุด/เครื่องมือเตรียมโมเดล | มีรุ่นที่เข้าคู่กับ r57.4 ใน ZIP นี้ |
| Python และ Ollama | ใช้ของเดิม ไม่ส่งตัวรันใหม่ |
| น้ำหนัก Typhoon และ BGE-M3 | ใช้ของเดิม ชื่อและ digest ตรงกัน ไม่ส่งน้ำหนักใหม่ |
| ประวัติแชท, logs, state, ไฟล์โมเดลของเครื่องผู้รับ | คงไว้ ไม่ใส่มาทับในชุดอัปเดต |

มีเพียงข้อมูลประกอบโมเดลขนาดเล็กใน `runtime/model_seed` เพื่อให้ตัวเปิดรุ่นใหม่ตรวจใช้โมเดลเดิมได้
ไม่ใช่น้ำหนักโมเดลหลาย GB หากเดิมใช้แบบดาวน์โหลดแต่ยังไม่เคยโหลดโมเดลจนเสร็จ การเปิดครั้งแรกยังต้องโหลดส่วนที่ขาด

ระบบตรวจไฟล์ก่อนเปลี่ยน และสำรองไฟล์ที่เปลี่ยนไว้ใน `_OldFlow_Update_Backups` ภายในโฟลเดอร์แชทเก่า
ถ้าแจ้ง `preflight_conflicts` ให้เก็บโฟลเดอร์เดิมและส่งรายการไฟล์ที่แจ้งกลับมา ไม่ต้องลบข้อมูลหรือคัดลอกทับเอง
ถ้าแจ้ง `program_running` ให้หยุดจากตัวหยุดของชุดเก่านั้นก่อน ตัวอัปเดตจะไม่ฆ่าหรือหยุดโปรแกรมอื่นให้เอง

นี่เป็น Flow เก่า **2026.10.10-service-r57.4** จากชุดส่งต่อที่ชื่อโฟลเดอร์ยังมี R56
ไม่รวม Flow ใหม่ R135 ที่กำลังพัฒนา และไม่ได้เปลี่ยนโมเดลไปเป็นรุ่นที่ใช้พัฒนา Flow ใหม่
ผลตรวจการประกอบ/อัปเดตแนบใน `UPDATE_VERIFICATION_TH.md`; ยังไม่ใช่การยืนยันว่าเปิดบนเครื่องผู้รับจริงแล้ว
